## Qwen4｜三粒度新架构：句范围 + 字候选 + 位判决（研究分支 Qwen，非生产）

> 演进说明：旧版猜想（p 作 KEEP 软先验**进判决**、以单字窗为主）已被取代。园长 2026-11-13 认可两条核心原则，并要求写入整体闭环的完整新架构，本节据此重写；E050 已验证证据保留于 §6（命门须引用）。生产 V1 冻结不动，本设计不涉及。

### 0. 园长已认可的两条核心原则（2026-11-13）

1. **判决彻底独立于 p**：p（及整句困惑度）只当「哪里危险」的定位提示，绝不进「该不该改」的判决余量。有 p 用 p 逐 token 定位，无 p 用整句困惑度粗定位或均匀注意；判决永远站在文本 + 检索佐证上，故无 p 也能跑（优雅降级）。
2. **整句只当上下文范围，不打包判决**：用数据自带句界（whisper 换行 / CTCDataset 标点）切句作为上下文范围；判决仍落在每个单字改动位（等长替换、按位计改对/误改），不接受/拒绝整句打包。

### 1. 对现有架构的质疑（已验证）

- **V1 完全依赖答案键**：`--no-candidates` 后七篇 0 改对 / 0 误改 / 距离 2024（与不纠错逐字相同）。候选表来自测试真值，样本外泛化为零（E049 洛神赋 oracle 0%）。
- **开放枚举灌废料**：同音/近音全进候选，目标被淹（E039 漏斗），计算量大、错改原料多。
- **自举偏置**：LM 自己提议候选又自己打分，会偏袒自己的提案。旧版靠声学 p 破循环，但 p 数据稀缺（§6）。新架构想用检索佐证补长程证据，但**模块分开 ≠ 证据独立**（Astra 审阅 §3）：检索若与 LM 同源、或查询依赖候选词，仍可能只是把 LM 记住的再端一遍。是否真有增量须实测「已有 G 时 R 还能否减少误改」，不能靠命名「独立」自证。

### 2. 完整新架构：三粒度数据流（结构闭环，承重假设待验证）

**三个粒度分清**（解开「2–4 窗到底是分词还是 N-gram」的旧困惑）：

- **句子＝上下文范围**：数据自带句界，无分词器。喂给 LM 左上下文 + 检索整句查询。
- **2–4 字串＝候选单位**：LM 句内多阶前缀遍历生成（这是分词跨度，不是 N-gram 阶数）。
- **单字＝编辑单位**：等长替换，按位判决。

**六个模块（按数据流，每个角色有主）：**

1. **句界切分**：用 whisper 换行（韵律段，可能半句）/ CTCDataset 标点（书面句，。？！干净）切句，不建词典、不分词。产出：句子＝上下文范围。真值本就按段标，句单位与真值粒度天然对齐。现有管线已按句处理（真值一行一句、对齐按句、上下文在句界重置），句界是直接用数据给的，不新增模块。
2. **危险提示（可选，只定位）**：有 p → 逐 token 标低 p 段（细，AUC 0.901）；无 p → 整句困惑度粗定位（只到句、定不到字，单个不显眼错字未必拉高整句困惑度）或均匀注意。只决定「去哪儿多看、多生成候选」。**红线：绝不进判决余量**，否则 p 又偷偷变回裁判。
3. **提议器（LM 前缀查找 + 检索，只提议不裁判）**：
   - 局部：以前文 h 为键，从 Trie/历史索引直接拉有据后继（前缀键值查找），动态 2–4 阶、最长优先。字链打分 `P(w₁w₂|h)=P(w₁|h)·P(w₂|h+w₁)` 原生就会。
   - **N-gram 必须双向用上下文（园长 2026-11-13 纠正）**：4-gram 的*预测历史*天然只有左 3 字，但*打分*不能只看左侧。给候选打分时要连同替换后受影响的右侧后继（≤3 字）一起重算，即「左上下文 + 候选 + 右受影响后缀」逐位累计，原文与候选同范围比较。`rag_clean.affected_scores` 已这么做；`context_clean.py`（E050 命门基线）只用左侧单字预测，须升级双向后重测，52%/64% 不能直接沿用（详见 §7）。
   - 长上下文：左 3 字够不到的远端线索（如「大将军出击匈奴，卫青率军出征」里「卫青」够不到「大将军」），靠检索（RAG，整句作查询）补长程原文证据。
   - 产出：候选字串注入竞争。LM 在此只提议，不裁判。
4. **读音过滤（硬筛）**：候选必须落同 base 池（忽略声调，平均约 67 字），phonetic_class 卡资格；读音不合直接出局。这是必要非充分条件。
5. **校验 + 位判决（文本 + 检索佐证，无 p）**：回答「该不该改」。证据＝双向上下文契合 G + 领域增量 D（检索佐证的可测形式）+ 校准好的背景余量 ρ。**R≡D，已对齐 formula.md（E052 定清楚，§9）**：检索佐证不另造未定义的 R、不引入 γ，就用既有明确定义的 D＝混合模型相对通用模型的增量（双向、对原文与候选对称、无证据时自动→0）；不能把 BM25 相关度、出现次数或「出现过」直接塞进判决。取证须对原文与候选**对称**：共用同一上下文范围、检索预算、去重证据池；查询尽量遮住待纠错字，避免「搜了卫青所以查到卫青」的自证；原文没搜到不算原文错。判决按位：候选须以校准余量胜过 KEEP 才改；多字候选重叠由「余量最大/最长优先」裁决，不需分词器。**E052 实测：D 在样本外 CTC 上零判决增益（§9），检索仍当实验项。**
6. **校准（数据分工，侧挂喂参数）**：判决层 ρ/α ← CTCDataset 88k 句对（留一交叉验证 LOVO，文本管够）；p 门槛 ← 7 个带真值视频（占 60% 的大视频 BV1uUak6pEdK 留作验证、不拟合）。判决不依赖声学，故海量文本即可校准，解了 p 稀缺；p 退化成简单阈值，不再把判决绑死在声学上。

**分词器为何可去掉**：多字校正单位由 LM 前缀遍历原生生成（拉 2–4 字后继、最长优先＝隐式分词）；显式分词器要带词典，会把正想甩掉的答案键/词表依赖请回来（V1 关候选归零是教训）；留着它就有两个「什么是词」的来源（分词词典 vs LM 证据）会打架。去掉后只剩 LM/检索一个来源，更自洽，并由「沿 Trie 走多字路径」天然接上字→词接缝。锚点交给模块2、重叠裁决交给模块5。（检索引擎内部建索引的切分是另一回事，不在此列。）

**公式（数学形式，已对齐 formula.md；R/ρ 经 E052 定清楚，见 §9）：**

- 提议·字链：`P(w₁w₂|h) = P(w₁|h)·P(w₂|h+w₁)`
- 双向上下文差 G（只累计替换改变的概率项：改动字 + 右受影响 ≤3 字，原文与候选同范围）：
  `G = Σ_{i∈受影响位} [log P_lm(候选_i | h_i) − log P_lm(原_i | h_i)]`，`h_i` 含左上下文，替换后右侧后继一并重算
- 判决打分：`S_t = a_k + β_k·G_t + D_t`（D 系数为 1，**无 γ·R 项**；R≡D＝双向领域增量，非 BM25/次数直塞）；`S_o = 0`（KEEP）
- 归一 + 不改：`P(t) = exp(S_t) / [1 + Σ_j exp(S_j) + ρ_k]`；**KEEP＝固定质量 1（S_o=0），ρ_k＝背景竞争质量，单一职责**（二者分开，不一职两用）；改 iff `max P ≥ 1−α`。ρ/α 须按 formula.md §六 多项 Logit 拟合（现 ρ=1 偏小、过自信，E052 §9）
- 定位（红线）：`危险 ∝ 低 p（或整句困惑度）`——只调注意，不进 S

### 3. 数据流（一句话串起）

原始文本 →〔模块1 句界〕→ 句子（上下文范围）→〔模块2 危险提示定锚点〕→〔模块3 LM 前缀遍历 + 检索提议候选〕→〔模块4 同音池硬筛〕→ 每改动位候选 + 证据 →〔模块5 文本 + 检索佐证独立校验，按位判决〕→ 校正文本 → 真值按位评分。模块6 侧挂：88k 文本校准 ρ/α 喂模块5，7 视频校准 p 门槛喂模块2。无 p 时模块2 退化为困惑度/均匀，其余不变。

### 4. 闭环检查

**已闭环（结构层面，每个角色有主）：**

- 提议与判决分离，各有其主；判决独立于 p（红线清楚）。
- 无 p 优雅降级（均匀/困惑度注意 + 同一套文本判决）。
- 长上下文靠检索、局部靠 N-gram，分工明确。
- 校准数据分工，解了 p 稀缺；分词器去掉、词表依赖少一处。
- 三粒度（句范围/字候选/位判决）各归其位，整句不打包判决。

**未闭环（承重假设未验证 / 数据风险，待验证）：**

1. **命门**：纯文本 + 检索佐证能否达到旧「p 进判决」的 82% 精度？现纯文本≈52%、p 只定位≈64%（E050 实测，§6；系左-only，双向重测见 §7#1）。差的约 18 点全押在检索佐证 + 长上下文。**E052 小切片初测：检索 D 净增益 0、从不翻转最优（§9）→ 命门未过，检索这条腿在 CTC 单字上没撑起增量。**整个方向成立与否系于此。
2. **检索佐证的独立性存疑 + 迄今净增益≈0**：模块分开不等于证据独立（Astra §3）；同源语料、或查询依赖候选词，检索都可能只是把 LM 记住的再端一遍。已验证：E044 补语料 +88 改对来自 N-gram 底座、检索净贡献 0；E035/E037/E038 七篇有无检索输出几乎逐字相同（唯一额外修复是「魏清获取→卫青霍去」4 字）。**E052 样本外 CTC 小切片再证：D 翻转最优 0/120、G-only/G+D/错域三臂逐格相同（§9）。**须实测「已有 G 时 R 还能否减少误改」，不能靠命名「独立」自证，也不能把提速当成有用。
3. **目标域检索语料可能不够**：维基文库是文言（713 万字）、Tatoeba 才 91 万字且 2 字锚点大量弃权；B站现代口语/产品名上检索佐证可能大面积「支持不足→弃权」。与 p 稀缺平行的另一数据风险。
4. **校准域偏移**：CTCDataset 是拼音型**文本**错字（87%），非**声学**错字，错误分布不同；同音池重叠可部分迁移，但「哪个字错」的先验不一样，参数未必迁到 ASR。
5. **提议器多阶遍历须有界**：去分词器后多字候选生成 + 重叠裁决全压提议器 + 判决层，候选量可能膨胀，须靠最长优先 + p 注意 + top-h 框住。

### 7. 看完 Astra 评估 + 代码核查后指出的问题（区分已验证 / 待验证）

1. **命门基线是左-only，须重测（已验证）**：`context_clean.py:97-104` 只用左 3 字历史做单字预测（docstring 明说「Single-character prediction uses left context」），E050 `evaluate.py:130` 走的正是这条 `score_positions`。故 §6 的 52%/64% 是**左-only**数字。`rag_clean.affected_scores` 已双向（左+候选+右≤3）。园长要求双向 → 命门基线须用双向重跑，不能直接拿 52%/64% 当起点。
2. **R 未定义、≠旧 D、ρ 双职（Astra §3）→ 已由 E052 定清楚（§9）**：原误标 `S=a+βG+γR`、`KEEP=log ρ` 已更正回 formula.md 既定定义：`S=a+βG+D`（R≡D，双向领域增量，系数 1，无 γ）、`KEEP=S_o=0`（固定质量 1）、`P(t)=exp(S_t)/[1+Σexp(S_j)+ρ]`（ρ＝背景竞争质量，单一职责）。**E052 实测 D 在样本外 CTC 上零判决增益**，故「另造 R」既无定义必要、也无实测价值；ρ 须拟合（现 ρ=1 过自信）。
3. **「检索=独立证据」说法错误（Astra §3，已在 §1/§4 更正）**：模块分开 ≠ 统计独立。
4. **检索迄今净增益≈0（已验证）**：E044 +88 来自 N-gram 底座、检索净 0；E035/E037/E038 有无检索几乎逐字相同。提速不改变「有没有用」，命门仍押在 R 能否在 G 之上减少误改。
5. **Python 运行时瓶颈（已验证数字）**：七篇 RAG 144–247s vs 无检索 ~22.5s vs V1 ~19–22s（Astra E035/E037/E038 日志，含并行验收、非独占基准）。瓶颈在 Python 递归 MKN 概率查询 + 每窗 FTS5 检索 + Python 循环转移计数。CTCDataset 88k 句 ≈ 13× 七篇 cue 量，按现速度不可接受 → 园长要求转 C++。
6. **C++ 现状（grep 确认）**：`src/` 无 MKN 4-gram、无 FTS5/BM25；只有 V1 + `DomainEvidence`（TSV 邻接计数 maps，非归一概率、非检索）。MKN LM 与检索目前全在 Python（`rag_clean.py`/`prepare_rag_package.py`）。C++ exe 已有 `--candidate-export` 出窗口。
7. **FTS5 二字词问题（Astra 研究文档 §4.1）**：默认 trigram 匹配不了 <3 字符词（如「卫青」），须二字串/词条索引。转 C++ 时索引方案要一并定。
8. **校准域偏移（Astra §4，待验证）**：CTCDataset 是拼音型**文本**错字（87%），非**声学**错字；88k 句多 ≠ 能校准 ASR 风险；82.2% 只是旧七篇特定配置，不能拿另一数据集的 82% 宣称追平。

### 8. RAG+N-gram 提供候选的 C++ 实现 + 提速方案（待园长批，未实施）

**总原则**：离线建包留 Python（一次性，不在测试循环）；运行时 LM 打分 + 检索 + 判决转 C++。**先逐字复现 Python 输出（正确性门），再谈提速与 88k**；提速是工程、不是质量结论，迁移期间不改分数/参数。

**8.1 分工与现状**
- 离线（Python 保留）：`prepare_rag_package.py` 训 LM、建 evidence.sqlite、预计算同音池/读音类、出 manifest+SHA。一次性。
- 运行时（转 C++）：MKN 概率查询、检索取证据、双向 affected-only 打分、posterior+KEEP+重叠裁决。
- 窗口：C++ exe `--candidate-export` 已出（begin,end,source,target）；可保留子进程，或全集成省 TSV 往返。

**8.2 数据结构（离线导出紧凑二进制）**
- LM：`model.json` → 二进制。稠密字 ID（uint16）、扁平有序 n-gram 计数数组（history→count，二分/哈希）、每历史预存 den/bo（避免运行时重算 sum）。MKN 回退改**迭代**（非递归）。
- 检索索引：二字汉字词 → 倒排表（doc_id, 位置）；离线预存 df/idf、doc 长度。**原生 C++ 倒排 + BM25**（最快），或 sqlite3 C API 复用 evidence.sqlite（少重写、留 FTS5 规划开销）。推荐原生倒排，sqlite 作交叉核对。
- 同音池/读音类：离线预计算 `by_first[len,base]`、`phonetic_class`，运行时查表。

**8.3 提速关键（针对检索时间）**
- **句级批量检索 + 缓存**：一句检索一次（非每窗），按查询 token 集缓存；证据集在句内多窗共享。
- **域转移计数预算一次**：`q(h,w)=(count+κp)/(total+κ)` 的 count/total 来自检索段，每证据集算一次，句内所有候选共享（现 Python 每窗重算）。
- **通用 LM 概率缓存**：同位多候选共享 `p(h,w)`，按 (h,w) 缓存；affected-only 增量打分，原文与候选只重算改动位 + 右≤3。
- 查询遮疑点（防自证，Python 已有，保留）；证据载荷封顶（256 字/块、8192 预算，保留）；top-h + 最长优先框住候选量。
- BM25 top-K 可加 early-termination（WAND/block-max）若倒排够大。

**8.4 正确性门（先于 88k）**
- 同包同参，C++ 端到端须**逐字复现** Python `rag_clean` 七篇输出（浮点容差内）；任何分歧如实报，不静默接受。
- LM 概率质量自检（对应 `Model.validate()`，Σ_w P(h,w)=1，误差 <1e-8）。
- 既有测试转红则暂停（园长规矩）。

**8.5 分阶段**
- 阶段0：冻结 Python 七篇基线输出 + SHA + 计时（参照）。
- 阶段1：C++ MKN LM + 二进制加载；单测概率质量 + 对固定窗匹配 Python `affected_scores`。

**已验证结论：**

1. **R≡D**：检索佐证的可测形式就是既有的双向领域增量 D，不另造未定义 R、不引入 γ。D 可测、对原文与候选对称、无证据自动→0。
2. **ρ＝背景竞争质量（单一职责），KEEP＝固定质量 1（S_o=0），二者分开**。ρ 是召回/精度刹车 + 校准旋钮：ρ↑→更少改动（改对、误改同步降）、后验更校准。ρ=1（现初值）偏小、过自信（α=0.3 时预测均值 0.930 vs 实测 0.833）；ρ=100 时 0.931 vs 0.935 贴近。**ρ≈100 只是小样本观察，不是生产推荐值**；须按 formula.md §六 多项 Logit 拟合。
3. **检索（D）在样本外 CTC 上零判决增益**：120 位子集，检索命中 120/120 文档，但 D≠0 候选仅 **382/5859＝6.5%**；**mean|D|=0.069 vs mean|G|=7.69**（小约 111 倍）；**D 翻转最优候选 0/120**；G-only / G+D / 错域 D 三臂在每个 ρ/α 逐格相同（α=0.3、ρ=1 均 **52 改对 / 0 误改 / 5 错到错**）。→ 命门里「差的约 18 点押在检索佐证」在本证据下不成立。
4. **覆盖天花板**：正例真值落同音池 **132/169＝78.1%**，其余 22% 是字形错（读音不同），同音提议器够不到→只能由 ρ 吸收。
5. **单字精度-召回墙在 CTC 复现**：FP=0 仅在 α≤0.1（召回≤32%）；α=0.3→70 改对/5 误改、α=0.5→75/8。→ 仍须走多字候选。
6. **双向打分跑通**（落实园长 2026-11-13 纠正）。

**对 C++ 迁移的影响（§8，研究建议待园长批）**：检索（D）当前无质量价值，**C++ 提速检索会加速一个无判决增益的部件**。应优先把 LM/提议/判决（G 才是真正起作用的证据）搬 C++；检索仍当实验项，等 D 在目标域显出价值再投入提速。

**口径限制**：小切片 569 位、**文本错字域（非声学 ASR）**、仅单字、开卷探针；ρ/α 扫描是敏感性诊断，**不是拟合后的生产设置**，不宣称泛化。D≈0 可能与证据库/三字条件转移覆盖有关；七篇历史上 D 曾起过一次作用（卫青，E037/E038），故 D 并非恒 0，只是极少决定判决。未改生产源码/词库/真值/评测口径；未提交、未合并（Git 归 Qwen3.8）。

## Astra｜2026-11-13：候选与判决证据的职责审阅（建议，未实施）

本节回答园长关于“RAG＋N-gram 能否合理提候选、公式的数据由谁提供”的问题。保留上文设计；以下建议尚未做新实验，不代表已批准改公式。本轮仅核读文档与既有结果，未跑新的质量评测。

### 1. 判断：可以承担提议，也可以提供评分数据，但尚未证明能可靠选对

N-gram 是短上下文的字串统计模型，可以提出此前语料里常见的后继字串；RAG 是检索资料的过程，可以从相关原文中取出人名、术语或表达，再按读音筛选。二者适合互补提议，不能保证正确答案一定被提出，也不能保证提出的常见写法就适合当前句子。

目前证据应分开看：

- E044 固定候选表的七篇开卷实验：补语料后正确修复由 6 字增到 94 字，误改 1 字；有无检索输出逐字相同。它证明该批语料改善了现有 N-gram 判决，不证明新提议器的答案覆盖率，也不证明检索无用。
- 上文 E050 记录的开放单字路径：无 p 时 40 改对、36 误改、2 错到错；p 只定位时 38/21/2。这说明摆脱答案表后已有一定修复能力，但离可靠仍远。它不是“2–4 字提议＋检索佐证”整体架构的验收结果。
- “四字模型只看左三字”描述单个后继预测；给完整改写评分时，可以连同未修改的右侧字重算受影响的后继概率，取得有限的右侧证据。不能仅凭改动字自身的左侧预测就声称比较了完整上下文。

### 2. 数据提供者：让公式消费可检查的数据，不让公式制造证据

| 公式需要什么 | 应由谁提供 | 需要附带的限制 |
|---|---|---|
| 通用上下文差 G | N-gram 评分器，对原文与每个候选计算同范围的上下文概率 | 包含受改写影响的右侧后继；记录未知字、回退阶数；概率高表示常见，不直接表示纠错正确 |
| 检索支持 R，或旧研究公式中的领域增量 D | 检索器取回原文；证据统计器检查位置、周围文字并按来源去重，再形成双方的支持统计 | 记录原文、来源、上下文、支持原文还是候选；候选词出现过不等于本处该改；检索相关度不能直接当正确概率 |
| 读音资格及差异类别 | 拼音模块及读音数据 | 只限定可能的识别混淆，不判定词义 |
| 保留原文的余量、证据权重、候选漏掉答案时的处理 | 离线校准实验，用固定提议流程产生的候选和人工标签估计 | 正确原文负例不可缺；参数必须在未参与拟合的数据检查；不能让每次检索临时决定 |
| 来源与可追溯的语料底座 | 数据维护方整理；运行时由加载器提供给检索器和统计器 | 保存来源组、重复关系、真实边界与偏移，不能只交一个总词频表 |

按 AGENTS 的人员分工：Qwen3.8 维护语料与读音等底座、执行测试；Astra/Deepseek 研究并实现取证计算和校准；Astra/Qwen4 审查数据含义与架构。具体任务分派仍依园长指令。无需为了“判决独立”立即增加第三个模型或逐词 LLM。

### 3. 必须纠正的推理：分开模块，不等于证据独立

同一个 N-gram 先提议再评分并非逻辑错误；问题在于，不能把“被它提出来”和“它给的概率高”当成两份独立支持。应该在完整提议和筛选之后校准判决，并包含未提出正确答案的情况。

同理，RAG 也参与提议时，取回候选所在的那条材料，不能仅因属于另一个模块就算独立确认。即便语料来源不同，查询方式与语言规律仍可能让两份证据相关。相反，同源语料保留的更长原文也可能提供短 N-gram 丢掉的信息，不能一概认定没有增益。要检验的是：已有 G 时，R 是否仍减少误改，而非给它命名为“独立证据”。

建议原文与候选共用相同上下文范围、检索预算和去重后的证据池；查询尽量不依赖待纠错字。确需候选扩展查询时，对双方对称执行并取并集，留下查询来源。原文也必须得到同样的支持检查，没搜到不能直接算原文错误。

上文新设想的 R 尚无确定可测定义，不能直接把 BM25、出现次数或“出现过”塞进 γR。原有公式文档的 D 是有明确定义的“混合模型相对通用模型的增量”，与新 R 不是同一个已验证量；未经比较不能互换或叠加。新归一公式中的 KEEP 与背景质量也须统一含义，避免同一个 ρ 同时承担两种不同职责。

### 4. 最小验证方向（未启动）

先冻结实际提议器，统计正确答案进入前 K 个候选的数量、遗漏数量和耗时，再在同一批候选上比较“只有 G”与“G＋可追溯检索证据”。同时保留错误领域资料对照。按原指标报告改对、误改、错到错及漏改，检查同样改对数量下是否减少误改。

CTCDataset 可用于机制试验和初步拟合，不能因有 88,520 句就认定能校准 ASR 风险；82.2% 只是旧七篇特定配置结果，不能拿另一个数据集的 82% 宣称追平。七篇只能继续明确标为开卷，洛神赋目前限窗长用途，未经批准不扩作判决验证。

结论：先检验这两个模块是否提供足量候选和额外有效证据；不要求检索“证明” N-gram 正确，不把短统计模型包装成语义裁判。证据不足保留原文。生产架构、公式、词库及真值本轮均不修改。
