# 新词库架构设计

## 一、设计原则

每个词库只负责一件事，禁止混用、越权。

* 词库收录不代表允许纠错。
* 词频高低不决定候选资格。
* 拼音只提供读音，不决定是否修改。

> 词库目录结构
> data/
> ├── ac/
> │   └── ac_lock.tsv             # AC锁定词
> │
> ├── vocabulary/
> │             ├── ocabulary.tsv          # 普通词典
> │             └── extvocabulary.tsv     # 拓展词库
> │
> ├── pronunciation/
> │           └── pronunciation.tsv       # 带调拼音
> │
> ├── frequency/
> │         ├── word_freq.tsv           # 词频
> │         └── char_freq.tsv           # 字频
> │
> ├── correction/
> │                   ├── candidates.tsv             # 明确的别名替换关系
> │
> └── generated/
>                       └── pinyin_index.bin        # 自动生成的倒排索引

## 二、词库分类

| 词库       | 数据来源            | 职责                       |
| ---------- | ------------------- | -------------------------- |
| AC 词库    | 人工维护、动态添加  | 精确匹配并锁定文字         |
| 候选词库   | 人工、真实语料、LLM | 提供目标词、别名及错误写法 |
| 基础词典   | 雾凇 base           | 普通词汇参考               |
| 拓展词典   | 雾凇 ext            | 补充普通词汇               |
| 词频库     | SUBTLEX-CH- WF      | 提供词频                   |
| 字频库     | SUBTLEX-CH-CHR      | 提供字频                   |
| 词语拼音库 | CC-CEDICT 等        | 提供词级读音和声调         |
| 单字拼音库 | 拼音数据源          | 补充单字读音和声调         |

## 三、候选词库

统一使用 `candidates.tsv`，字段如下：

| 目标词 | 拼音     | 别称 | 来源         | 状态 |
| ------ | -------- | ---- | ------------ | ---- |
| 微信   | wei1xin4 | 维信 | 人工确认     | 1    |
| 微信   | wei1xin4 | 薇信 | 真实语料挖掘 | 1    |
| 微信   | wei1xin4 | 威信 | LLM 提议     | 0    |

规则：

* 一个别称占一行。
* 来源可信度：人工确认 > 真实语料挖掘 > LLM 提议。
* LLM 提议默认停用，未经确认不得自动启用。
* 状态：1 启用，0 停用。
* 别称只是候选证据，不代表任何上下文都必须替换。

## 四、拼音倒排索引

* 从已启用的候选词库自动生成。
* 结合词语拼音库建立读音索引。
* 单字拼音库用于补充，不可靠的读音标记为未知。
* 不允许人工维护第二套候选名单。
* 生成 BIN 用于加速加载和检索，源数据变化时自动重建。

## 五、AC 锁定规则

* AC 只有 LOCK 一种动作。
* AC 命中位置不可修改。
* 动态窗口允许跨越 AC 锁定区域。
* 锁定文字可以参与上下文判断。
* 候选只能修改未锁定部分，必须保证锁定文字原样保留。

**原则：锁定的是文字，不是窗口。**

## 六、统一数据格式

内部词库统一使用 UTF-8 TSV：

* 原始外部词库保留原格式。
* 处理后的正式词库统一转换为 TSV。
* BIN 等索引文件由程序自动生成，不允许人工修改。
* 每份外部数据记录来源、版本、许可和 SHA256。

## 七、最终纠错流程

```
AC 匹配并锁定
      ↓
文本切分与动态窗口
      ↓
候选词库检索
      ↓
拼音距离判断
      ↓
词频、字频评分
      ↓
候选竞争
      ↓
修改未锁定文字
```

**最终原则：AC 负责保护，候选词库负责提供修改目标，普通词典负责词汇参考，拼音负责读音，频率负责评分。各司其职，互不越权。**

### 8.2 上下文表的职责边界（各司其职，延续 §一 原则）

* 只做一件事：回答"**这两个写法里，哪个更贴合它周围的字**"。它不参与候选准入，不决定谁是候选，不覆盖 `frequency/` 的词频。
* 只允许扣分，不允许加分放行（`context_one_sided`）：实测同一权重，双边放行会让近音改写从 81 涨到 131–134、误改 100→192/202；单边只否决则误改降到 82。
* 来源与许可：Tatoeba 中文句库（CC BY 2.0 FR，89,289 句 / 916,062 汉字），衍生表同样标注 CC BY；已写进 `data/PROVENANCE.tsv`。
* 语料只用公开文本，**未使用本项目任何真值**。

### 8.3 默认评分口径变更（园长发话）

生产默认 = M1（原文缺词级证据时用字频独立估计）+ M2（该估计封顶 K=0.6）+ 上下文跨度 2、权重 1.0、单边否决。旧口径全部可用参数复现：`--no-ctx-evidence` 回到 M1+M2；`--no-ctx-evidence --missing-evidence veto` 回到 E022 冻结基线。次数口径（`--legacy-data/--word-freq/--no-candidates`）自动退回 veto 且不启用上下文，历史数字不受影响。
