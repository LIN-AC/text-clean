## E023｜Zipf 退步原因定位（漏斗 + 最小消融，只读，2026-11-07）

HEAD `877b6a2ef489b1b3a7dcd7b4ef0a7f7028193689`；指标逐字复用 E022 口径，先验证 counts 194/97/1927、zipf 20/86/2090、零操作 2024 与 E022 完全一致；漏斗探针 7 篇 stdout 与生产二进制逐字节相同。消融 B/C 用 `experiments/E023/probe/` 源码副本独立编译，**未改生产公式、词库、真值**。

五臂结果（改对字／误改字／总编辑距离）：零操作 0/0/2024；旧次数 194/97/1927；新Zipf 20/86/**2090（比不改还差66）**；消融B（恢复旧缺频策略）235/184/1973；消融C（Zipf域恢复旧字符频率补偿）230/140/**1934**。

漏斗（同一 55,224 窗口，zipf vs counts）：窗口级首音节门 13,132、无候选 21,409 两臂相同；**「原文无词频证据→整窗弃权」zipf 拦 9,680 而 counts 为 0**；最终采纳 64 vs 201。丢失改对归因（107 编辑／175 字）：原文缺证据 **89 编辑／141 字（81%）**、差额不够 15／24、目标词缺证据 3／10。配对级可改率（357 对，d=0）：旧 111 vs 新 **18**。

**结论：退步主因不是 Zipf 单位换算，而是"缺证据即弃权"这条策略**——它把旧口径里"原文查不到词频"这个**最大的改写给分项**（`fO=0 → logR=ln(1+fC)`，恰是 ASR 错字形态）反转成整窗否决。证据：消融 C 全程用 Zipf 尺度，改对字 20→230、距离 2090→1934，几乎追平旧口径。次因是通用语料与领域热词冲突（109 个双侧有证据配对里 82 个"错词反而更常见"，方向天然相反，换库/调阈值都救不了）。实现核对：`2.302585×(zipfC−zipfO)` 系数正确；缺失用 optional 不用 0 正确；**`ours_count` 不接入评分是正确决定**（领域计数来自本次评测真值，接入即泄漏）。发现留白：`char_freq.tsv` 被读入后在 Zipf 模式下**无任何消费者**，所以"恢复字符补偿"必须新增读取路径而非开开关。

最小修改建议（待批准，本轮未实施）：M1 缺原文证据时改用 `Σzipf(字) − 9×(n−1)` 估计；M2 给该估计加常数上限 `max(估计, zipfC − K)`，K∈{1,1.5,2,3} 扫曲线（不许先动 λ/μ）；M3 处理 115 个无词频证据的启用目标词（停用或补不泄漏来源）；M4 把缺证据策略做成 `--missing-evidence=veto|char|capped`，让消融与生产同源。数据/SHA/命令/逐视频结果见 `experiments/E023/README.md` 与 `results/manifest.json`、`results/diagnosis.json`。

已知限制：全部开卷；1,921 个可归因错字里 zipf 臂仍剩 1,901；误改字 86 里含把正确 `文景→闻名`、`时局→实际` 改错的新错误，不因指标改善而掩盖。

## E029｜单字纠错实测：加 `--target-char-freq` 让单字走字频表，检验上轮估算（2026-11-08）

两条机制性发现：① **R3 全 0 的真正原因是默认"原文查不到词频就不改"**——单字原文在词级表里必然查不到，整窗先被弃权挡掉；必须叠控制臂（M1 用字频估原文档、M2 封顶）才谈得上单字纠错，所以单字开关必须和 M1/M2 成对评估，之前把"开关"当成独立一步是我表述不清。② 单字改动的分数优势很薄（多在刚过门槛处），会把本来能改对的多字修复挤掉，所以 R6 的改对字反而比 R5 少 52。

**公共记录更正（E028 第四节估算口径偏低）**：E028 离线估算给的是"640 个未修复同音单字里 18% 改对、35% 白改、47% 改错"，方向正确但**代价低估约 2.4 倍**。原因是估算只统计了"没修好的错字"这一人群，完全没有统计"**本来就写对的字**"——真实系统里凡同音字里存在更高字频的候选就会把正确文本改错，这部分正是实测的 457 处误改；另外估算没有竞争环节的损失。正确口径应为：**单字纠错精度约 7.5%（48/637），总错误量 1977→2478，比不纠错（2024）还差 454**。今后凡评估"放宽某类改写"的收益，必须同时统计本来正确的位点，不能只在未修复样本里算。

结论：`--target-char-freq` 保持默认关，本轮数据不支持打开；单字那 70.6% 的损失需要词组/上下文级证据，不是频率或窗口参数能解决的。数据见 `experiments/E029/results/single_char_run.json`，对照基准仍为 E027 冻结值。

## E040｜RAG 为什么检索不到能区分候选的证据（2026-11-11，Deepseek，只读）
