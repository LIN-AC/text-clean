# 设计决策及理由

## D-1 实验基线锚定 commit `14aad46`（Qwen，2026-11-03）

所有 E1–E3 结果均以该 commit 为被测版本，`git diff HEAD -- src include CMakeLists.txt` 已核实为空。
**理由**：本轮工作区曾出现源码版本与读取内容不一致（同一文件两次读取行数不同），不锚定 commit 的数字无法比较。后续 Agent 改动 `src/` 后请另起新基线条目。

## D-2 CTCDataset 按需拉取且不入库（Qwen，2026-11-03）

`datasets/` 加入 .gitignore。上游声明**仅限学术研究用途**，且整仓 171 MB 含大量语法类数据。
**做法**：放弃 `git clone`，用 raw.githubusercontent.com 单文件 curl 取 20 个拼音型拼写纠错文件（18 MB）。
**理由**：许可要求与仓库体积都要守；语法纠错类数据集与「同音错字」任务无关，拉下来只会干扰指标。

## D-3 评测协议：train 建词表 / test 打分（Qwen，2026-11-03）

- 词表只从 train 划分派生（6,553 规范词 / 14,320 别名），只在 test 划分上计算指标。
- 句间以 `\n` 拼接后一次性喂给 CLI：换行是非汉字边界，天然隔离逐句候选窗口；不传标题/简介，即「空上下文等价旧行为」这条既有不变量。
- 指标采用 CSC 社区常规的字级 detection 与 correction 双套 P/R/F0.5，句级整句修好数为辅。
**理由**：本仓此前无真值数据，若不限定 train/test，别名会从测试集泄漏；换行拼接保证一次调用可跑数万句（逐句起进程约需 15 分钟以上）。

## D-4 放弃「调 λ/μ 阈值」路线（Qwen，2026-11-03）

依据 E3 扫描：μ 0.7→1.8、λ→1.2、max-distance 2→1 全部组合下 det_P 停在 0.031–0.038，fp 恒为 tp 约 25 倍，参数只在等比例削减召回与假阳之间移动。
**决策**：改进优先级放在**证据模型结构**（别名权威化 D2、读音上下文化 D3、分数改造 D4、重叠选择区间 DP D5），阈值扫描不再作为独立优化方向。
**理由**：这是有实测支撑的否证，继续调参会把基准时间花在无效搜索上。

## D-5 token 概率 `p` 只进准入层，不进替换判定（Qwen，2026-11-03）

依据 E1：错字 vs 正确 AUC 0.874（排序可用），但 8.6% 错字 `p≥0.99`、幻觉段 AUC 仅 0.672 且 70% 的 token `p≥0.98`。
**决策**：`p` 用于片级/段级准入与候选排序（全片 mean `p`<0.85 判音乐/强噪素材；段内 `min(p)`<0.5 时禁用该段 `context_bonus`）；**不作为字级替换门限**，幻觉段改用结构规则（复读检测、模板表、段首极低 p + 段均高 p 的形态）。
**理由**：字级门限的最优 F1 仅 0.261，且高置信同音错字恰是本项目主目标，`p` 对它们完全失明。

## D-6 CyIME 只取机制，不引入其代码与数据（Qwen，2026-11-03）

上游 `github.com/Cyletix/CyIME` 根目录 `LICENSE` 是 **GPL-3.0**（GitHub API 未检出，需以文件为准）。
**决策**：参考副本只留在 `log/cyime/`（gitignore），记录取回文件的 sha；本仓任何实现均为独立重写（`tools/reading_freq_probe.py` 用我们自己的表算相对频率），不复制其源码、不引入其词典数据。
**理由**：许可不兼容风险 + 我们要的是可迁移的机制，不是依赖。

## D-7 罕见读音惩罚不进改写门，改走「词级读音证据 + 软惩罚」（Qwen，2026-11-03，依据 E6）

**依据**：cscd-ns/test 前 2,000 句实测——读音稀有度对 fp/tp 的 AUC=0.512；只有 2.4% 改动位置用到无词级证据的读音；上游默认阈值 τ=-1 下杀 13.4% fp 却杀 27.9% tp，所有工作点都是 tp 损失更大。同时 fp 的真实主因是 `fO=0` 用整串词频判定，虚词组合天然无词条（的/是/在/被 四字的 fp 占单样本 fp 的四分之一强，前 20 字占 31.6%）。
**决策**：
1. 不实现「按读音稀有度否决候选」的硬门；
2. 数据模型上迁移其核心结构：把 `字 → 读音集合` 升级为 `(词, 读音) → 频率`，让原文侧读音由切分结果上下文化选定，稀有度以 `ln(evidence/该词条主读 evidence)` 作为**进 ΔS 的加性惩罚项**（可配、不单独跨零否决）；
3. 修 D3 的实际优先级让位给修 D4/新增「字频+bigram 合法性」口径。
**理由**：输入法是多候选排序、惩罚为软、错误代价对称；本仓是二值改写门且 tp 基数极小（61–62），同一机制在此代价结构下净损。

## D-8 「原文合法性」判据必须重写，并列为 P0（Qwen，2026-11-03，依据 E7）

**依据**：E7 在全部 test 划分（80,336 个改写片段）实测——被改写窗口里 `fO=0` 占 99.5%–100%，fp:tp = 17.7:1，`freq0` 特征 AUC=0.501；正确文本中 83.4% 的 2–4 字窗口本身就查不到词。单一硬否决不可用：`cooccur==0` 选择性 0.75、`splits_token` 0.91（会把正确修复一起杀光），只有 `pmi<0`（24.4）与 `min_char_unigram≥5000`（7.1）有选择性但覆盖不足。
**决策**：
1. 合法性判定由「单一整串词频」改为**多项组合证据**（字频、bigram PMI、构词完整性、词典命中），作为 ΔS 的加性项而不是新增硬门——单一硬门已被实测否证；
2. 消除口径不对称：候选侧 `kHotwordFrequencyFloor` 与原文侧必须同口径，或取消地板并显式要求「存在正向证据才可改写」；
3. `dict.txt` 自带的频率列要么正式纳入融合（声明量纲与合并语义），要么在文档里写明弃用理由——现在是「存在但无声弃用」；`WordFrequency::add_word` 的 `max()` 合并语义也要一并声明。
**理由**：这是所有下游改动的上游瓶颈。假前提率 83% 不降，D2（别名权威化）与 D5（区间 DP）带来的召回增量会被同一批噪声淹没，无法归因。
**验收线**：fp:tp 从 17.7:1 降到 <3:1，且 E3 基准的 tp 绝对数不下降。

## D-9 原文侧改用字符独立基线，候选侧取消热词地板（Deepseek，2026-11-03，依据 E8）

**背景**：D-8 要求把「原文合法性」从单一整串词频改成多项组合证据，并消除 `kHotwordFrequencyFloor` 与裸 `count()` 的口径不对称。E8 实测了其中可判定的部分。

**决策**：
1. 新增 `CharFrequency`：从 `data/dict.txt`（jieba 格式）只取单字行（11,580 字、总量 2.71×10⁷），定义
   `expected_count(span) = total × Π p(c)`，`p(c) = (count(c)+0.5)/(total+0.5)`。
   它是 bigram PMI 的分母，含义是「未收录片段按字独立假设本该出现多少次」。
2. 打分两侧同口径：`fO_eff = fO>0 ? fO : expected_count(O)`；候选侧删除 `kHotwordFrequencyFloor=3`，用真实词频。`ΔS = ln((1+fC)/(1+fO_eff)) − λd − μ`，λ/μ 与距离上限均不动（遵守 D-4）。
3. 数据缺失即退回旧口径（`CharFrequency` 为空 → `fO_eff=0`）；CLI 提供 `--char-freq` 与 `--no-char-baseline`，后者精确复现 14aad46（A/B 已验证：cscd-ns/test 前 2,000 句 det_P 0.0306 / tp 179 / fp 5,678）。
4. 字频数据源复用 `data/dict.txt`，不新增数据文件；`Vocabulary` 仍是「membership only」，字频由独立加载器读取同一文件。

**理由**：E8 全 test —— det_P 0.0991→0.1269、cor_F0.5 0.0148→0.0196、tp 12,039→12,300、fp 109,406→84,613、整句修好 1,117→1,403；窗口级 fp:tp 17.31→11.71。零证据通道 `fO=0 ∧ d≤1 ∧ fC≥3 ⇒ 0.0363` 不再成立；E5 的两处 `有信→微信` 消失，参考完全一致 2/10→3/10。

**已知代价与未决项**：
- 唯一证据是地板的**小频热词**失去准入（30 篇里 `微新→微信`，fC=3、d=1，被一起删掉）。恢复它要靠 D2/E6 的候选侧可追溯证据（`source`/`doc_support`），不能加回地板。
- d=2 通道仍占剩余 fp 的 61.6%（97.8:1）。是否把 `max-distance` 默认改为 1 是产品决策：d≤1 时 fp:tp 3.59、整句修好 2,602，但 tp −12.4%。
- **D-8 的验收线（<3:1 且 tp 不降）未达成**：E8 的 ROC/规则扫描表明窗口内特征上限 AUC 0.864，保留 99% tp 时 fp 几乎不降，单靠原文侧证据到不了 3:1。建议按 status.md 的「P0 验收线重述」执行；D-8 的 3:1 目标转入候选侧项目。

## D-10 本轮 p 实验边界（Astra，2026-11-04）

按用户明确要求，仅进行离线独立判别实验，p不加入ΔS，不修改算法或人工标注。E13说明p对检错有增量但候选修复判别无稳定收益，因此不据此落实D-5的具体门限；段级软排序/原文弱保护为待后续验证方向，不是已批准上线的规则。未标注区域保持未知，高p不能充当正确真值。详见 `P_INDEPENDENT_EXPERIMENT.md`。

## D-11 候选侧归因以「长度分层」为对照基线；两个工作点待决策（Qwen，2026-11-04，依据 E20）

**边界（本轮已守）**：只做离线实验与测量。门控写在 `log/cand_scope/scope_gate.h`，由 `build.py` 按唯一锚点插入 `src/text_cleaner.cpp` 的**副本**编译；生产源码、评分公式、λ/μ（遵守 D-4）、正式词典、7 份人工真值均未改，SHA 前后逐条断言。没有同时引入构词/PMI/新边界规则（遵守 E19 的要求），每个臂只动一个变量，全部完整重跑而非从基线输出删编辑。

**已判定（有实测支撑，后续实验必须遵守）**：
1. **候选词表的「来源」标签不是因果因素，候选长度才是。** 同一张大表（CSC＋THU 成语）只准入 4 字候选后，7 篇上的改写集合与「默认小表＋成语」逐条完全相同（d2 46/46、d1 33/33，0 差异）——小表 7,884 条里 7,875 条本来就是 4 字。**理由**：E15 的 THU 成员/DF≥2、E16 的 source/训练句支持、E19 的来源支持都在比较「不同来源的表」，而这些表彼此的长度分布也不同；不给长度对照，来源归因无效。今后任何「按来源筛候选」的实验都必须附一条「同表按长度分层」的对照臂。
2. **3 字层可以直接剔除**：大表 d2 全 7 篇 129 条 3 字候选只有 1 个 TP、128 个坏候选（新六篇 0 TP / 58 坏）。跨域同样是坏编辑占优（sighan15 19 对/207 坏、cscd-ns 9/320、lemon 2/300）。
3. **「拼音更严」与「距离更小」不是两个独立旋钮**：`max-distance=1` 时候选池内已无 grade≥2 的候选（新六篇与历史都为 0），拼音门在 d1 下完全饱和；它的独立价值只存在于 d=2。**理由**：E16 的 13 组门控里有 4 组是在 d1 下测拼音级，那几组的差异不可能来自拼音级本身。

**待决策（proposal，未采纳、未上线）**：
- 安全优先工作点 `len4_py2_d2`（只准入 4 字候选 ＋ grade≤2）：7 篇总编辑距离 2024→1981、字符 45 对/4 坏、正确文本 0 误改（基线 608 字）、召回 2.3%；跨 5 个域都不使总误差变差。
- 召回优先工作点 `lens24_chg1_yield_py2_d2`（剔 3 字层 ＋ 2 字候选只准改 1 字 ＋ 被更长候选严格包含的短候选让位 ＋ grade≤2）：字符 56 对/689 坏 vs 基线 55/2,616（召回持平、损害 −74%），跨 5 域 −72%～−83%；仍未到净收益。
- 「让位」单独上线（不改准入）：窗口 TP 22→42、字符 TP 55→83、字符假阳 +10，实现面 `src/text_cleaner.cpp:386-405` 约 10 行。
- 验收线 A1 重定义：现行「保留 ≥95% 基线改对字符」与 A2/A3 互斥（过 A1 的 4 个臂全是保留 2 字通道的臂）。建议改为「相对不改的净收益 ≥0」或「字符级坏编辑 ≤ 字符级 TP」，与 D-8 的 3:1 一并决策。

**理由（为什么这些只是 proposal）**：v1.2.3 仍因 `test_cli_context` 回归暂缓，任何默认参数改动都会与发布门禁耦合；且 4 字工作点的召回只有 2.3%，把它设成默认等于把工具变成「只改成语」，属产品定位决策，不是算法决策。
