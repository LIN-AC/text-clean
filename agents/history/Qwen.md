### 读到的两个核心机制（我自己的表述）
1. **读音不是字的属性，而是「词+读音」这行的属性**。他们为同一个词的多条读音行各算一个相对量：以该词自身主读为分母取对数比，低于阈值的读音单独成表，供解码层做**软惩罚**。要点在于分母是「同一个词条自己的主读」，所以 16.8% 有多读音的字不会被一刀切。
2. **词频融合纪律**（三条最有用）：
   - 不可比的统计不放进同一个数值竞争：用户层与系统层权重刻度不同，他们用显式优先级规则（同名时留用户词、用户词不受候选池上限）而不是让数字大小决定；文档里也明确拒绝把「接字条件统计」当独立词频用，只导出原始计数，归一化交给排序层。
   - 融合前做量纲校验：合并两份词库时，先确认两边频次中位数不倒挂，才原值保留、不缩放；去重键是 `(词条, 规范化编码)`，只追加主表缺失的组合，来源内部首现胜出。
   - 准入门是双阈值 + 读音可确定性分流：出现次数 ≥3 **且** 文档支持度 ≥2 才候选收；读音被词表唯一确定的自动接受，多读音/无读音的导出成人工复核清单而不是猜。另有音节闭包校验（新条目音节必须已在主表音节集，否则丢弃并计数），且融合结果写成独立扩展表由主表引用，不改主表本体。

### 我的假设被自己的数据否证（重要）
H2「罕见读音黑名单能修掉 D3」——**否证**。我按同一形式自建了 `(字,读音)→频率`（本仓 `word_freq.txt` 的词用 pypinyin `heteronym=True` 展开全部被证实读音，权重取词频；8,131 格 / 5,437 字），在 cscd-ns/test 前 2,000 句上重放：
- 读音稀有度对 fp/tp 的 **AUC=0.512**（等于无区分力）；改动位置里只有 **2.4%** 用到「无任何词级证据」的读音。
- 任何 τ 下 tp 损失都大于 fp 收益：τ=-1（上游默认）杀 13.4% fp 却杀 27.9% tp；τ=0 杀 27.2% fp / 63.9% tp。
- **fp 的真实主因是频率口径**：`fO=0` 用整串词频判定，虚词两字组合天然没有词条 → 全被当作不成词错字。fp 最高的字是 的(691)、是(134)、在(126)、被(85)，前 20 字占 31.6%。
- 对照规则「含高频虚词且整串无词频 → 否决」在 N=50 时杀 44.7% fp / 29.0% tp（高频字表用文本自身 unigram，前 170 字覆盖 50% 文本量，不用标签）。

**教训**：上游是输入法候选排序（多候选互相竞争、惩罚是软的、错误代价对称）；我们是二值改写门，且 tp 基数极小（61–62），同一机制迁移过来代价结构完全不同。以后先问「错误代价是否对称」再迁移机制。

## 2026-11-03 第三轮：测清「原文合法性」并定为 P0（E7 / D-8）

按指示优先做这一件事，结果比预想更靠前——**问题不在阈值，在判据本身退化**。

### 测法上的一个坑（记给其他人）
用 stdout 与输入的逐位 diff 还原改写片段时，**相邻的两个窗口会被合并成一个更长的串**，导致 span 级统计失真（我第一次算出「fp 有 54% 命中 dict.txt」，与代码里「命中即跳过」直接矛盾）。必须按窗口长度切开后重算：真实窗口的 `in_vocab` 只有 0.4%–1.6%，否决门是正常工作的。span 级 AUC 表因此只作为信号排序参考，结论以窗口级表格 + 全窗口假前提率为准（后者不依赖还原）。

### 三层根因
1. `WordFrequency::count()` 精确查询、未命中返回 0（`src/word_frequency.cpp:130`），这就是本仓全部的「原文是否合法」判断；正确中文里 83.4% 的片段本来就查不到词 → 它标识的是「词典没收录」，不是「像错字」。
2. 候选侧地板 3、原文侧裸 0 的不对称，使 `fO=0 ∧ d≤1` 恒有 ΔS=0.0363>0：**零正证据即可改写**。E7 的 fp:tp=17.7:1 就是这个区的体积，和 E2 探针里的常数完全对上。
3. `dict.txt` 每行自带频率列却被 `vocabulary.h:6-7` 无声弃用；`add_word` 用 `max()` 而非累加——本仓实际存在三种未声明的频率口径，这正好是上一轮 CyIME 词表融合问题在我们身上的体现。

### 我自己被否证的一个猜测
我原以为「切开词典词」（`splits_token`）会是高选择性信号，实测 0.91——因为正确修复的片段同样常切开词典词。同理 `cooccur==0` 选择性 0.75。**任何单一硬否决都会把 tp 一起杀掉**，所以 D-8 明确写成「组合证据加进 ΔS，不加新硬门」。

### 已落到的公共位置
EXPERIMENTS 加 E7；DECISIONS 加 D-8；status.md 的待办顶部插入 P0 块（含验收线 fp:tp <3:1 且 tp 绝对数不降），并把原「字频+bigram」待办标记为已测量。Deepseek 的两条待办原样保留、未改顺序。

### 我怎么建模的

- 门控我改成「每个轴一个环境变量」（`TC_SCOPE_MINLEN/MAXLEN/LENS/PY/MAXCHANGED/MAXCHANGED2/YIELD/CMP/MARGIN`）而不是 Astra 的 mode 字符串，好处是 41 个臂自由组合、不用重编译；代价是必须证明「旋钮全关＝生产行为」，这条用与 `probe.exe` 的对跑断言覆盖。

### 结论（数字与表格在 E20 / D-11 / `CANDIDATE_SCOPE_EXPERIMENT.md`）
1. **小表优势＝候选长度，不是成语来源**：大表只准入 4 字候选后，与「默认小表＋成语」的改写集合逐条相同（46/46、33/33）。E15/E16/E19 三轮的来源归因都缺这条对照。
2. **3 字层是纯噪声**（7 篇 129 条候选 → 1 TP / 128 坏），可以直接剔。
3. **假阳的主体来自准入，不是竞争**：单候选分量占 53%–68%，而它们在源码里是无条件应用的（`j == i + 1 ||`）。
4. **竞争的代价是召回**：池内可用 TP 有 7/8（新六篇）与 22/43（历史）没被应用，其中 3 与 12 例是输给同分量里的高频短候选（`街头巷围→街头巷尾` 输给 `香味`、`穷兵独武→穷兵黩武` 输给 `病毒`）——就是 E12 记的「高频同音压过专名」，这次在候选侧量到了。
5. **拼音门在 d1 下饱和**（池内无 grade≥2 候选），所以「拼音更严」和「距离更小」不是两个独立旋钮；拼音的独立价值只在 d2，且只在窄范围里才划算。
6. 两个工作点：安全优先 `len4_py2_d2`（总距离 2024→1981、字符 45 对/4 坏、正确文本 0 误改、召回 2.3%）；召回优先复合臂（召回持平、损害 −74%，跨 5 域 −72%～−83%）。**都没有上线**，参数决策留给用户。

### 我自己差点犯的四类错（记下来给别人省时间）
1. 一开始想用「按长度过滤词表」代替改代码，因为候选长度＝窗口长度＝词条音节数，看起来完全等价。**不等价**：`max_syllables` 是由词表最长条目推出来的，过滤词表会顺带改变窗口生成长度上限。这批数据上结果可能一样，但那是巧合不是机制。教训：「能改数据就别改代码」的直觉，在数据同时驱动别的参数时会失效。
2. 差点实现一个「每窗口只留分数最高的 N 个候选」的竞争旋钮。写之前重读分量循环才发现判决只用**最高分与次高分**，删掉第 3 名以后是空操作（N=1 才有效，而那等于「全部无条件应用」）。教训：加旋钮前先把判决公式读一遍。
3. 跨域等值断言第一次失败（sighan15 差 45 行），我第一反应是怀疑自己的门控。用「同输入、我的 exe vs Astra 的 exe 当场对跑」一步排除，根因是 `data/word.txt` 在 E16→E19 之间被用户更新过（新增 0–9/他她它，AC 锁集变了）。教训：等值断言失败先做二进制对跑，再查数据版本，最后才动自己的实现。这条也意味着 **E16 的跨域绝对值今天不可直接复现**，已写进 E20 与 status 待办并 @Astra。
4. 汇总脚本第一版把 retention 全算成 0（`results` 外层键是臂名，我按视频名去取 base），是打印出来看见一排 0 才发现。教训：派生指标先看一个非零样例再跑全量。

### 待验证假设（证据不足，不进公共结论）
- **H1**：4 字层的召回瓶颈只是词表（现有表最长条目 4 字，5 字以上目标从未被评估）。扩 5–8 字成语/术语（用户真值里的 `卖官鬻爵`、`轻徭薄赋`、`以见居为簿`、`苟利社稷死生以之` 都是现成的正例）应能提召回而不带进 2 字层的噪声。可测：只准入 ≥4 字，跑同一套。
- **H2**：「让位」的正确形式可能不是「严格包含」，而是「同分量内更长者优先」——等长并列的情况我现在完全没处理。要先看分量内等长候选的 TP/FP 分布。
