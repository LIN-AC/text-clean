## 二、实验方向与当前架构设计

### 1. 生产 V1（现行默认，本轮不动）

流程：AC 上锁 → 汉字段切分与分词 → 窗口枚举（分词许可 permit / 跨界 edge）→ 首音节门 → 拼音倒排取候选 →
拼音编辑距离硬过滤 → 词频证据打分 → 候选 vs KEEP → 非重叠替换。

关键参数与位置：窗口长度 2–4（`max_window_syllables=4`，`include/text_clean/text_cleaner.h:44`；
`window_max=min(max_syllables,4)`，`src/text_cleaner.cpp:244`）；`min_syllables_for_exact_pinyin=2`；
拼音距离上限 2；每窗候选上限 64；判决 `ΔS=2.302585·(ZipfC−ZipfO)`；
上下文证据 `context_span=2`、**单边只扣分**（`src/text_cleaner.cpp:440-477`）、锚点计数 <3 弃权；
KEEP 恒以 0 分参与比较。**注意：窗长 2–4 说的是"候选词窗口"，与"N-gram 阶数（历史 3 字）"是两层东西，别混。**

### 2. 研究入口 RAG＋字符 4-gram（Astra/Qwen4，`tools/rag_clean.py`，须加 `--research`）

FTS5 二字 token BM25 检索取证据段 → 字符 MKN 4-gram（order 4，合并语料包 vocab 10,606）算双向 G →
`S=a+βG+D`、`P(t)=exp(S)/[1+Σexp(S_j)+ρ]`，改 iff `max P ≥ 1−α`；
当前初值 a=0、β=1、κ=10、ρ=1、α=0.01、H=30、retrieval_limit=50，**均未校准**（α 没拟合是已知缺陷）。
已验证：有检索与无检索七篇输出逐字相同（E044，D≠0 窗口仅 13/1,174）→ +88 的收益全来自 4-gram 底座的语料扩充。

### 3. 三粒度新架构（Qwen4 设计，`agents/Architecture.md` §0–§9，未实施）

园长已认可两条原则：**判决彻底独立于 p**（p 只当"哪里危险"的定位提示，绝不进判决余量）；
**整句只当上下文范围，不打包判决**（判决仍落在每个改动位）。
三粒度＝句（上下文范围）／2–4 字串（候选单位，是分词跨度、不是 N-gram 阶数）／单字（编辑单位，等长替换）。
六模块＝句界 → 危险提示（可选）→ 提议器（LM 前缀遍历＋检索，只提议不裁判）→ 同音池硬筛 →
文本＋检索佐证的位判决 → 离线校准（ρ/α 用 88k 文本对，p 门槛用 7 视频）。
分词器拟去掉：多字单位由 LM 遍历原生生成，留着词典会把刚甩掉的答案键依赖请回来。

**命门（整个方向押在这一条）**：纯文本＋检索佐证能否追平旧"p 进判决"的 82% 精度？
现状 52%（无 p）／64%（p 只定位）（E050），且**这两个数是左-only 上下文算的，双向重测后才能当起点**；
E052 初测 D 零增益 → **命门未过**。其余未闭环：检索独立性存疑（模块分开≠证据独立）、
目标域检索语料可能不够、CTCDataset 域偏移、提议器候选量须有界。

### 4. Astra 的职责审阅结论（11-13，Architecture 审阅节）

N-gram 与 RAG **可以承担提议，也可以提供评分数据，但尚未证明能可靠选对**。证据分工：
G 由 N-gram 评分器给（必须含受改写影响的右侧后继）；D/R 由"检索取回原文＋证据统计器按来源去重"给；
读音资格由拼音模块给；余量与权重由离线校准给（**校准集必须含"本来就该保留"的正确原文负例**）。
三条硬规矩：不能把"词出现过／检索相关度高"当成正确性；查询尽量不依赖待纠错字、原文与候选**对称取证**；
原文没搜到不能算原文错。最小验证方向：冻结提议器 → 统计正确答案进前 K 的数量、漏多少、耗时 →
同批候选比"只有 G"vs"G＋可追溯检索证据"，并保留错领域对照。

### 5. 园长已批准的 V2 分步实现（E053，Astra，第一步已验收）

1. 候选不读 `candidates.tsv`/`competitors.json`：N-gram 用 2/3/4 阶前缀索引生成 2–4 字路径、保留原文前缀、
   有界 beam=8，逐字同音基音硬筛（允许异调，本阶段不扩近音）；RAG 从真实连续段＋至多 3 字真实前缀
   取等长读音匹配字串，不跨句拼接。
2. 检索转原生 C++/SQLite（`tc_retrieve`）：按 cue 取证，最多 8 个二字上下文锚点＋最多 4 对原文/提议写法对称查询，
   汇入同一证据池，≤300 段 / 8192 字，去重复段，截断不造 EOS。
3. 判决沿用 formula.md 原值（R≡D、KEEP 质量 1、ρ 只表背景竞争），p 不参与；候选集合变了，旧校准不能沿用。
4. 冲突裁决：同一连通重叠组意见不同则整组保留原文（不采用"余量最大/最长优先"的贪心）。
5. 迁移边界：本步只把检索查询、候选分支、重排、证据载荷转 C++，N-gram 提议与判决仍在 Python——
   **不能叫"全 C++ 纠错器"**。

验收要分开记：迁移是否逐字一致、V1 是否不变、新候选覆盖率、RAG 补候选与 D 参与判决是否有收益。
E053 已有完整 README、逐视频结果、源码/输入 SHA 和复现命令。工程 26/26，28 组 C++/Python 旧查询完全一致，V1 七篇逐字节不变。RAG 补候选多改对 15 字、多误改 7 字；同池进一步加 D 多改对 32 字、多误改 90 字。CTC 90 句 N-gram 为 11 改对/5 误改，加 RAG 为 12/7。默认 KEEP，只有 research 执行修改；研究模式默认 D=0，显式开关才加 D。完整 C++ 模型迁移、全量关 AC/错领域对照尚未做，不宣称质量发布或泛化通过。

### 6. 本地 LLM 路线（E051 开出，未批）

已量到的事实：同音桶（公开词表 214,622 个读音串，不依赖本项目词库）能为任意片段造出"可犯的同音错写法"；
14b 量化模型在给定两版时的判别力（正例 88.6%／负例误改 1.4%）远高于现行判决层在同位点的表现（5.7%）；成本 0.25 秒/条。

并单独测"让 LLM 自己指认错字"的召回侧（本轮完全没测）。它可能与 E053 的检索佐证互补，也可能取代其中一环，需园长按优先级定。
