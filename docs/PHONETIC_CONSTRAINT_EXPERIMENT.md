# 拼音约束与候选可靠性实验（E16，2026-11-04，Astra）

结论：不宜只允许完全同音，也不宜让完全同音在冲突中自动胜出。更值得继续验证的是分级准入：保留仅一次声调差异的修复能力，对单字 in/ing、en/eng 混淆使用窄范围来源证据例外。通用来源/支持度硬门收益不足；本轮所有主要收紧方案仍未达到保留原基线95%正确修复的要求，未部署生产配置。

## 2. 拼音分级与来源定义

对候选每个对应音节，寻找字典允许读音组合中的最小差异，再取窗口中最严重等级：

1. **exact**：声母、韵母、声调相同且声调已知；
2. **tone**：声母、韵母相同，声调不同（含未知声调，不能冒称完全同音）；
3. **nasal**：只允许同前缀的 in↔ing、en↔eng；
4. **other**：其余现有近音门放行的差异。

目标读音仍约束为词表声明的无声调音节；输入保留字典全部读音。因此这里是“字典允许的同音”，不是经过词级消歧的真实发音。`立 li4,wei4` 仍会把“立国立民→为国为民”视为完全同音，strict无法解决此问题。

可靠性信号严格分开：

- `source`：THUOCL成语或历史名人成员；`external2`：此外真实DF≥2。DF只用于准入，不混入本项目词频。
- `train2`：既有训练划分中至少两个**去重目标句**出现该候选。训练数据没有文档ID，这只是句子支持代理，不是真正doc_support。
- `multisource`：至少两个语料家族（SIGHAN、MCSCSet、ECSpell）出现候选；不把SIGHAN不同年份冒充不同家族。
- `support_union`：external2或train2；`tone_support`：该联合证据再与同声韵约束组合。

只有训练target计数，没有使用ASR或测试真值建表。训练与本轮三套测试target整句完全重复数均为0，但这不能排除近重复或证明整篇文档独立。候选中external2支持7,894条、train2支持5,642条、跨家族支持3,343条。

## 3. 各差异等级在基线中的实际贡献

以下是当前基线已选编辑的分层，不能当成新门控重跑后的结果：

| 等级 | ASR TP / FP / 错到错 | 异域 TP / FP / 错到错 |
|---|---:|---:|
| 完全同音 | 10 / 6 / 12 | 110 / 1154 / 37 |
| 仅声调 | 7 / 7 / 14 | 52 / 1378 / 48 |
| in/ing、en/eng | 0 / 0 / 3 | 5 / 33 / 2 |
| 其他近音 | 2 / 7 / 66 | 28 / 4164 / 229 |

“其他近音”是最大坏编辑来源，但里面仍有正确修复。完全同音也远非正确性保证。基线ASR鼻音TP为0，重跑后却恢复了一个鼻音TP，直接说明只过滤最终命中会得出错误结论。

## 4. 第一轮：固定评分，完整重跑

FP仅指改坏正确原文；错到错单列。表为编辑窗口数量，异域汇总5,100句。

| 准入方式 | ASR TP / FP / 错到错 | 异域 TP / FP / 错到错 | 正确文本误改 |
|---|---:|---:|---:|
| 基线 | 19 / 20 / 95 | 195 / 6729 / 316 | 388 |
| 仅完全同音 strict | 21 / 11 / 19 | 133 / 1753 / 72 | 101 |
| 同声韵，允许声调不同 tone | 27 / 17 / 38 | 190 / 3534 / 145 | 279 |
| tone＋无条件鼻音混淆 | 28 / 17 / 40 | 197 / 3594 / 148 | 278 |
| tone＋单字鼻音＋联合支持证据 | 28 / 17 / 38 | 197 / 3546 / 146 | 279 |
| 冲突中优先完全同音 | 30 / 23 / 97 | 215 / 6993 / 325 | 398 |
| 现有距离上限1对照 | 27 / 17 / 34 | 190 / 3259 / 131 | 259 |

“优先完全同音”在同一重叠连通分量内有正分exact时仅从exact竞争；保留原分数与胜出差值，不额外加分。它提高召回却增加误改，因此不适合直接作为当前保守工具的优先策略。

tone允许累计两处声调差异，距离1最多容纳一次。tone相对距离1在ASR没有增加TP，却增加4个错到错；异域窗口TP也未增加，FP增加275、错到错增加14（字符级仍有少量不同得失），本轮不支持全面放开多处声调差异。

鼻音联合条件相对无条件鼻音：异域TP197全保留，正确原文FP3594→3546，错到错148→146；ASRTP28不变、错到错40→38。相对tone仍新增7TP，同时新增12FP和1错到错，收益不是免费获得的。

全局硬门没有理想工作点：THU成员严重损失通用修复，训练句重复/跨语料家族偏向常见片段，ASR大量正确编辑反而被删除。THU成员与DF≥2结果相同，**本轮未证明DF阈值本身具有超出来源成员资格的独立增益**。训练句支持也不能包装成已验证的文档支持机制。

## 6. 根据首轮结果追加的窄例外

这是事后探索的两组确认实验，不冒称预注册或全新盲测：保留距离≤1的原准入，仅允许一个改动字的鼻音差异越过该限制（原距离仍记2、评分仍扣2λ）。分别要求联合支持或仅真实外部DF≥2。

| 方式 | ASR TP / FP / 错到错 / 未知 | 异域 TP / FP / 错到错 | 正确文本误改 |
|---|---:|---:|---:|
| 距离1 | 27 / 17 / 34 / 580 | 190 / 3259 / 131 | 259 |
| 距离1＋单字鼻音＋联合支持 | 28 / 17 / 34 / 585 | 197 / 3271 / 132 | 259 |
| 距离1＋单字鼻音＋外部DF≥2 | 28 / 17 / 34 / 580 | 191 / 3259 / 131 | 259 |

最窄外部证据例外仅新增两处已确认正确编辑：

- ASR：兵令城下→兵临城下。
- lemon/nov：大义灭清→大义灭亲。

距离1组原有ASR38个、异域205个改对字符全部保留，没有新增已知坏编辑。扩大到训练句支持后额外获得异域6个TP，但新增12FP和1错到错。说明来源证据更适合作少量高风险候选的附加条件，而非全局替换许可。

## 7. 必须报告的原修复损失

净TP增长可能掩盖原有修复消失。下表按**同一个原始字符位置仍被改对**计算保留率：

| 方式 | 保留ASR基线31个改对字符 | 保留异域基线226个改对字符 |
|---|---:|---:|
| strict | 14（45.2%） | 117（51.8%） |
| tone | 25（80.6%） | 177（78.3%） |
| tone＋条件鼻音 | 25（80.6%） | 182（80.5%） |
| 完全同音优先 | 31（100%） | 220（97.3%） |
| 联合支持全局门 | 28（90.3%） | 224（99.1%） |
| 距离1 | 25（80.6%） | 171（75.7%） |
| 距离1＋外部证据鼻音例外 | 25（80.6%） | 172（76.1%） |

窄例外组合相对基线坏编辑ASR115→51、异域7045→3390，但仍丢原正确修复，未满足“≥95%保留且坏编辑减少≥30%”的原验收。完全同音优先虽保留较多，却让坏编辑增长。不能把这些方案称为已达标的生产改进。

若用更严格的相同窗口/相同替换作为原TP身份，窄例外组合保留ASR17/19、异域160/195；strict仅保留10/19、110/195。两种口径均未过95%保留线。

## 8. 下一步方向与局限

研究重点转向**分级拼音准入＋非常有限的例外**，不继续堆叠通用评分特征。不同声调应保留一定空间，完全同音不自动获得冲突优先权；常见鼻音仅作有独立词条来源的窄例外。暂不启用全局source/doc_support硬门，不动态化λ/μ，不改生产默认max-distance。

下一步若继续，优先审计收紧后丢失的既有TP是否有可追溯的词级读音/目标词证据，验证能否恢复这些原修复；不通过调低全局阈值补回。完全同音仍可能依赖稀有异读，这个问题并未因strict而解决。

数据仅一个稀疏标注历史视频及已有CSC测试；ASR数百未知编辑没有被当正确，无法宣称总体精确率。首音节门、候选64上限、词级自动读音均未改，结论仅适用于当前可检索候选范围。未做性能承诺。

## 9. 复现与资产

```powershell
powershell -File log/phonetic/build.ps1
python log/phonetic/run.py
python log/phonetic/run.py --followup
```

需先有E15/E14实验输入和词表。构建脚本只写实验目录；所有修改在复制的pipeline中。`protocol.json`/`run_protocol.json`/`initial_run_protocol.json`/`followup_protocol.json`记录参数、训练文件及二进制哈希；`protected.json`记录生产输入哈希；`support_details.json`逐词记录来源/DF/去重句支持；`overlap_audit.json`记录训练测试整句重复检查；`results.json`、`summary.json`及各组诊断/逐编辑文件记录结果。首轮13组、后续2组，全部完整重跑候选选择。
