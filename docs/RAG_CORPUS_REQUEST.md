# RAG 语料补充需求（交给 Qwen）

2026-11-11，Deepseek。依据 [E040](../experiments/E040/README.md) 和 [E041](../experiments/E041/README.md) 的实测结果，向 Qwen 提出下一批语料交付要求。**先补语料，再优化检索；本轮不改生产代码、词库、真值、评分规则或默认值。**

## 0. 一句话说明

E041 在 116 个 V1 正确位点上发现：**69 个（59.5%）的正确目标词在同领域语料里根本不存在**；剩下 47 个里当前上下文检索只取回 2 个，改成候选词查询能取回 47 个，但目标/错误候选的文档支持是 37 对 10（目标存在组）。所以现在缺两样：

1. **补对地方的语料**：现代口语/书面、历史领域、带自然上下文，不是再抓一批通用大语料；
2. **补完之后再做候选条件化检索**：否则没有证据可检索。

完整数字、失败机理见 E040/E041 README，本文只写交付要求。**这些统计来自七篇开卷，只用于定位缺口；补语料不等于泛化通过，之后仍需独立日常 ASR 真值验证。**

### Qwen 先做这 5 步

1. 读本文 + [RAG_CORPUS_TARGETS.tsv](RAG_CORPUS_TARGETS.tsv) + [RAG_DATA_CONTRACT.md](RAG_DATA_CONTRACT.md)。
2. 列来源清单（URL/书名、许可、SHA、字数、domain/register/source_family），确认可抓/可用。
3. 建 `build/e042_corpus/corpus_supplement.sqlite`，按契约字段。
4. 跑硬性检查（偏移、去重、泄漏、许可）并生成逐词 `coverage_report.tsv`。
5. 交 `manifest.json` + `README.md`；覆盖不足标 `BLOCKED + 原因`，不要造模板/不要改评分。

## 1. 为什么需要这批语料（实测缺口）

- 116 个 V1 正确位点：**69 个目标词同领域查无**（42 个 H 里只有目标词、没有错误竞争候选；27 个有错误候选但目标词查无）。
- 现代视频 15 个位点，**13 个**目标词同领域查无；历史 101 个里 56 个查无。
- 现有训练包：现代段正文 818,860 字、历史 5,696,023 字；包内 607,006 个短段，平均 10.7 字/段。
- 用全量包（含 9,011 个留出簇）模拟补语料，目标词召回只从 47 到 49；**补现有留出簇不够**。
- 错误候选常常更常见：`政治` 73 篇 vs `正在` 470 篇；`田亩` 18 vs `田赋` 68；`政务` 0（现代）vs `征服` 12；`返乡` 0 vs `翻墙` 2。**补通用高频语料可能把错误方向喂得更大。**

## 2. 需要补什么

### 2.1 现代语料（P0，最优先）

**规模目标**：新增 **3,000 万汉字**，最低 **1,000 万汉字**（沿用园长备忘录/E031 的 3,000 万字目标）；至少 **10 个独立来源组**（source_family），不要用同一网站/同一本书复制多份充数。

**构成建议**（可按实际来源调整，但要在 manifest 里报实际数）：

| 类型 | 目标量 | 说明 |
|---|---:|---|
| 现代口语/字幕/访谈 | 1,000 万字 | ASR 的真实使用场景；自然口语，不是书面范文 |
| 新闻/评论/说明文 | 1,000 万字 | 政务、社会、经济、日常 |
| 社媒/论坛/生活分享 | 500 万字 | 近十年、自然表达；注意许可 |
| 其他现代书面 | 500 万字 | 科普、教程、问答等 |

**必须覆盖的 6 个 P0 目标词**（每个至少 **20 篇独立文档、3 个来源组**，自然上下文，不能只出现词条）：

| 目标词 | 当前同领域文档 | 需要补的语境 |
|---|---:|---|
| 段首 | 0 | 排版/文档/段落开头 |
| 政务 | 0（全库 46 篇都在历史域） | 政务服务/政务公开/政务大厅等现代用法 |
| 做到严而有度 | 0 | 管理/教育等自然短语；若判定不是自然词，请报告，不要造模板 |
| 返乡 | 0 | 春运/春节/农民工返乡等 |
| 配齐 | 0 | 配齐人员/设备/班子等 |
| 错时 | 0（全库 2 篇） | 错时上下班/错时停车/错时开放等 |

### 2.2 历史/领域语料（P1）

**规模目标**：新增 **500 万汉字**，至少 **3 部/3 个新的独立来源组**，不要只把现有四部书再切一遍。优先经济、财政、行政、社会、河工、人物类史料；公有领域或可署名许可。

**必须覆盖的 14 个 P1 目标词**（每个至少 **10 篇独立文档、2 个来源组**）：

`桑弘羊`（30 个位点）、`祥符决口`（6）、`会要辑`（3）、`富裕`、`清账`、`纸币`、`节流`、`起价`、`跨地`、`前线`、`税基`、`衣冠南渡`、`账册`、`鹿皮币`。

注意：

- `桑弘羊` 在当前 E038 训练包里 0 篇，但 E033 旧库里曾有 19 段——说明是语料版本/书目覆盖问题，不是词不存在。
- `会要辑` 可能是切分拼接词；如果确认不是自然词，请报告“不可覆盖”，**不要为了凑数造句子**。
- `纸币`/`富裕`/`前线` 在全库其他领域有少量文档；需要的是**同领域**的自然上下文。

### 2.3 对比语境（P2-context）

这 4 个词目标词存在，但错误候选更常见，需要“目标词作正确词”的对比语境，每个至少 **20 篇**：

| 目标词 | 当前同领域 | 错误候选示例（仅供理解偏置，不要写进语料） |
|---|---:|---|
| 政治 | 73 | 正在 470 |
| 田亩 | 18 | 田赋 68 |
| 民变 | 19 | 民间 149 |
| 青苗 | 1 | 情面 7 |

要求：自然句/段，目标词在句中作正确用法；不要只堆词频，不要用“词语解释/词典条目”。

### 2.4 低覆盖与保持（P2-low / P3）

- P2-low：`青黄`、`南伐`、`句丽`、`对峙`、`最称`，每个至少 10 篇、2 个来源组。
- P3：已有 15 篇以上的词（`兼并`、`豪强`、`盐铁`、`八部`、`前代`、`后世`、`将有`、`明亡`、`江南`、`进士`、`仁政`）保持，补上下文多样性即可，不要求冲量。
- 完整 40 个唯一目标词、优先级、当前文档数在 [RAG_CORPUS_TARGETS.tsv](RAG_CORPUS_TARGETS.tsv)。表里的 `current_docs_domain/current_docs_all` 是 **E038 训练包**口径；全量包会略高，以实际重建后的包为准。

### 2.5 来源建议（仅供参考，许可优先）

- **现代新闻/书面**：中文维基百科（CC BY-SA）、明确开放许可的新闻/科普/教程/问答；不要用版权不明的整站转载。
- **现代口语/字幕**：有明确许可的公开访谈、播客转写、字幕/口语语料；许可不清的不要用，也不要用本项目测试字幕。
- **历史**：维基文库的公有领域史书/会典/方志及其 CC BY-SA 转录；汉代/经济类可看《史記》《漢書》《資治通鑑》《通典》《文獻通考》，明清类可看《明實錄》《清史稿》《續文獻通考》《大清會典》等；优先补现有四部书之外的作品。
- 任何来源都要在 `source_list.tsv` 写清 URL/书名、许可、SHA、字数、source_family；拿不准许可的，先报给园长，不要先入库。

## 3. 数据格式与目录

### 3.1 交付到新目录

交付到 **`build/e042_corpus/`**（全新目录，不覆盖 `build/e036_corpus/`、`build/e038_*` 或任何已有包）：

```
build/e042_corpus/
  corpus_supplement.sqlite      # 新增语料，字段见下
  manifest.json                 # 来源、许可、SHA、版本、数量、检查结果
  coverage_report.tsv           # 每个目标词的覆盖报告
  source_list.tsv               # 每个来源：URL/书名、许可、SHA、字数、来源组
  README.md                     # 批次说明、已知限制、复现命令
```

如果新增语料与原 E036 库结构不同，可以另存 `corpus_supplement.sqlite`；不要原地改 E036 的 `corpus.sqlite`。后续由 Deepseek/Astra 用 `tools/prepare_rag_package.py` 重建新包。

### 3.2 `docs` / `segs` 字段

严格沿用 [RAG_DATA_CONTRACT.md](RAG_DATA_CONTRACT.md) 的字段；新增批次字段可以加列，但不能删原列、不能改语义。

`docs` 至少包含：

| 字段 | 要求 |
|---|---|
| `doc_id` | 稳定 ID，不因排序/重分块改变 |
| `domain` | `现代` / `历史`，不许混 |
| `register` | 新增：口语/字幕/访谈/新闻/社媒/书面/古籍等 |
| `period` | 新增：大致年代（如 2015–2024；古籍写朝代/版本） |
| `work` / `title` | 书名/站点/栏目 |
| `url` / `license` / `src_sha` | 具体出处、许可、原始文件 SHA256；不许用网站首页代替 |
| `fetched_at` | 抓取时间 |
| `cluster_id` | 完全相同/确认近重复的文档簇 ID |
| `source_family` | 同一书/同一网站/同一转载链的来源组 |
| `text_raw` / `text_norm` | 原始正文 / 规范化正文；非汉字用空格保留，不把两边拼起来 |
| `normalization_map_json` / `normalization_version` | 规范化位置可回查 |

`segs` 至少包含：`seg_id`、`doc_id`、`ord`、`off`（Unicode 字符偏移，不是字节）、`text_norm`、`chars`、`boundary_kind`（真实句号/原文献行/自然段等）。**不要把 250 字块首伪装成句首，不要重叠计数。**

### 3.3 编码与换行

- UTF-8、无 BOM；TSV 用 LF；SQLite 文本统一 UTF-8。
- 所有偏移以 Unicode 字符计；任何“合并空格/繁简转换”必须留映射。

## 4. 质量与验收

### 4.1 硬性检查

- SQLite 完整性；所有 `segs` 能由全文 + `off` 复原；无空文档、破损 UTF-8、未知许可。
- **泄漏 0**：不得读取或使用 `asr/`、`temp_txt/`、`clean_txt/`、`whisper-test/`、人工真值、本项目字幕来选句或造句；用现有 3,094 个 12 字窗口做泄漏复查，命中必须为 0。
- **去重**：报完全重复、近重复、跨 cluster 重复数量；独立文档数按 `cluster_id` 计，同一文档多段只算 1。
- **来源多样性**：现代至少 10 个 source_family；历史至少 3 个新来源组；单个来源不超过该批总量的 30%（历史古籍可按实际放宽，但要报）。
- **自然性**：目标词必须出现在完整自然句/段中，不是词表、词典释义、标题堆砌、模板句；人工抽查至少 30 条。

### 4.2 覆盖验收

| 组 | 目标 | 最低验收 |
|---|---|---|
| P0 现代 6 词 | 每个 ≥20 独立文档、≥3 来源组 | 6/6 达标 |
| P1 历史 14 词 | 每个 ≥10 独立文档、≥2 来源组 | 至少 12/14；不足的逐词报原因 |
| P2-context 4 词 | 每个 ≥20 篇对比语境 | 4/4 |
| P2-low 5 词 | 每个 ≥10 独立文档、≥2 来源组 | 5/5 |
| P3 11 词 | 保持现有覆盖，补上下文多样性 | 不下降 |

**不允许用“总字数够了”代替逐词覆盖**；`coverage_report.tsv` 必须逐词一行：

```
target  docs_total  docs_modern  docs_historical  source_families  sample_context  status
```

`sample_context` 给 20–40 字的公开自然句片段（不能来自 ASR/真值/测试字幕），用于人工抽查。

### 4.3 不可覆盖怎么办

如果某个目标词：

- 不是自然词（如 `会要辑` 可能是切分拼接）；
- 公开来源里确实找不到足够自然语境；
- 许可不允许；

请**明确报告“不可覆盖 + 原因 + 已尝试来源”**，不要造模板句、不要用 LLM 生成句、不要把词表/释义当语料、不要用测试字幕反查。覆盖报告里标 `BLOCKED`，不要为了达标改数字。

## 5. 明确禁止

1. 不得使用 `asr/`、`temp_txt/`、`clean_txt/`、`whisper-test/`、人工真值或本项目字幕来选句/造句。
2. 不得用 LLM 生成、模板拼接、词典释义、词表、标题列表冒充自然语料。
3. 不得把同一来源复制成多个 doc_id/source_family 充数；不得伪造去重/独立文档数。
4. 不得修改 `data/correction/candidates.tsv`、正式词库、人工真值、评分规则。
5. 不得覆盖 `build/e036_corpus/`、`build/e038_*` 或已有运行包；只交付新目录。
6. 不得用目标词清单去检索本项目测试视频/字幕；清单只用于核对公开语料覆盖。
