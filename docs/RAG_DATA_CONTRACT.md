# 交给Qwen：RAG＋N-gram数据交付规范 v1

2026-11-11，Astra。依据本轮已经运行的消费者接口反推，替代“再扩大一点词库”这种不明确的任务。**先交可检验的小版本，再扩覆盖；不要覆盖正式data或人工真值。**字段和来源比词条数量更重要。

## 先看结论和分工

算法第一版已实现：C++导出经过锁定/窗口/读音约束的候选；Python读取资料、计算字符4-gram通用概率与领域混合概率，再与KEEP/背景竞争词一起判决。旧词频不进入新判决。

Qwen需要交的是**有句界、有身份、有出处、可去重的原文资料，以及有完整读音的竞争词**。不要直接交一张更大的词频表；不要填写a、β、ρ、κ或风险阈值，这些由Astra做模型估计和验证。当前参数只是未校准的工程初值，不是数据质量目标。

本轮已有可运行样品包：`build/e035_package/`，由E033资料派生，不作为正式词库发布。其消费者为 `tools/rag_clean.py`，构建器为 `tools/prepare_rag_package.py`。下面先规定原料接口，再说明实际运行包；Qwen优先交原料，不必自行实现另一套公式。

## 1. 最高优先级：文档原料库 corpus.sqlite

沿用E033数据库，不另起服务。新增字段时保留原字段，另存新版本，不原地覆盖E033。SQLite文本统一UTF-8，所有offset以Unicode字符为单位，禁止UTF-8字节偏移。

### docs：一行一个来源文档

| 字段 | 类型 | 内容及约束 |
|---|---|---|
| doc_id | INTEGER PRIMARY KEY | 稳定ID，不因排序或重新分块而改变 |
| domain | TEXT NOT NULL | 首版仍为 `现代` / `历史`；现代用于通用模型，历史只供领域检索 |
| work、title | TEXT | 书名/站点和篇章标题，现代口语句也保留其来源身份 |
| url、license、src_sha | TEXT NOT NULL | 具体出处、许可、原始文件SHA256；不要用网站首页替代具体来源 |
| fetched_at | TEXT | 抓取时间，不伪装成出版年代 |
| cluster_id | TEXT NOT NULL | 去重文档簇ID，完全相同和确认近重复转载共享ID |
| source_family | TEXT NOT NULL | 同一书/转载链/母语料的来源组，供留出验证和防重复计权 |
| text_raw | TEXT NOT NULL | 未丢标点的原始正文 |
| text_norm | TEXT NOT NULL | 繁简规范化后的全文；非汉字是边界，用空格保留，不把两边连起来 |
| normalization_map_json | TEXT NOT NULL | 规范化字符索引到原文索引的数组；转换和合并空格也必须可回查 |
| normalization_version | TEXT NOT NULL | 映射表/转换工具的版本与SHA |

一行可能是一卷史书，也可能是一条独立现代句；不要为了增加“文档数”把同一句复制成十个ID。同簇不同原文仍保留docs各行以便核查，派生模型计数每簇最多贡献一次。首版构建器选择同簇第一份正文，所以**只合并可互相替代的重复文档**；不要把整本书所有不同章节误合为一个簇。

当前兼容构建器已经识别docs的 `cluster_id/text_norm`，存在时直接使用全文，避免分块重叠重建。`source_family/text_raw/normalization_map_json`作为原料审计资料必须提供；首版运行包尚不利用它们拟合参数，不代表可以不交。

当前E033适配器将`work`暂存为运行包的`source_family`，尚未把新版原料的来源组原样传入；也不替代上述原料的全部验收。Qwen交新版后，Astra须补齐字段传递与原料校验，再构建正式候选包，不能把当前兼容适配器当成完整格式验收器。

### segs：完整句/可定位自然段，不是任意切下来的字块

| 字段 | 类型 | 约束 |
|---|---|---|
| seg_id | INTEGER PRIMARY KEY | 稳定ID |
| doc_id | INTEGER | 引用docs |
| ord | INTEGER | 文档内顺序 |
| off | INTEGER | 本段在docs.text_norm中的起始字符位置 |
| text_norm | TEXT | 必须等于全文对应切片 |
| chars | INTEGER | `len(text_norm)`，不是字节数 |

检索可以分块，概率计数必须恢复真实句界。不得把250字块首人为变成句首，也不得把重叠24字重复计数。完整正文、真实边界和offset都在时，算法侧可以重新构建检索块和模型句子。

当前消费者为简化首版，按text_norm空格切汉字连续段；因此日期、小数、英文被分隔是**明确限制**。保留text_raw和映射，便于以后统一处理；本轮不要自行把数字等归一成另一个词形，也不要改真值口径。

### 原料验收

- 外键均有效；所有段均能由全文与off复原；没有空文档、破损UTF-8、未知许可。
- 完全重复和近重复分别报数量，跨cluster重复另列。证明不是通过把所有文档合一来“去重”。
- 标明现代口语、现代书面、历史原文的体量与来源组，不能把古文补到“通用现代语料”里充数。
- 不读取asr真值、已纠正文本、评测答案来选择句子或造搭配。近重复检查结果要留存；0个12字命中不能叫绝对无泄漏。
- 给出固定的训练/留出文档簇清单，同一source_family尽量不跨两边。模型留出数据与ASR真值是两回事。

## 2. 第二优先级：完整词级读音与非目标竞争词

继续复用 `pronunciation.tsv`、`pronunciation_char.tsv`，正式更改仍按项目规则审批。先在交付目录提交建议版本与差异，**不能自动启用候选词**。

- 词级单位是完整读音变体：例如一整条 `wei1xin4`。多音词不能把不同变体的位置自由拼接。
- 每条读音标来源与可靠性；未知调/未知读音独立记录，不当同音同调。
- 普通同音词、品牌、人名、术语，即便不允许改写，也要能进入竞争集合。词条存在只赋予“竞争”资格，不赋予“替换目标”资格。
- 替换权限仍只来自已有启用候选表和C++实际导出的候选；停用项、普通词、Mask不得越权。
- AC热词另有hot标记，等长且满足音素条件时不受新模型前30名截断；AC对原文位置的锁定仍由C++负责。
- 不按静态词频排序竞争词，不因低频删词。先报缺完整读音、缺通用字符覆盖、超长词和未知调的数量。
- 实体异写另交“目标实体ID、词形、出处、适用范围、是否歧义、人工状态”；自动子序列/同书共现仅是建议，不能直接宣称同义。

现有普通读音表已派生108,967个2–6字竞争词；这不是108,967个允许修改的目标。此规模证明接口可用，不代表人物/品牌覆盖已足够。

## 3. 通用N-gram原料：交完整计数依据，不交伪概率

优先交第1节可回查的现代完整句子，Astra使用同一构建器训练字符4-gram。若同时交计数，必须是**未经候选筛选、未经频次裁剪**的1–4阶原始计数，以及词表、句首/句末、UNK映射规则；保留低计数才能估计改良Kneser–Ney折扣。

共同字符集合V：所有预测字符＋`?`(UNK)＋`$`(EOS)；`^`(BOS)只作历史条件。这里三种符号是内部保留标记，不是原文字符。当前构建器将训练出现少于2次的汉字映射UNK，固定规则并记录。不能把未知字随意赋0.1次数再声称是概率。

现代、历史必须共享该字符映射。领域计数是在通用V上统计，不能悄悄另开一张字表。原文/候选出现V外汉字时当前实现保留原文，需把这类漏纠列出来，而非用UNK相等证明两个词同样合理。

需要报：留出句子的未知字率、1/2/3/4阶实际使用率、按领域的留出困惑度、概率总和检查。**低未知字率不等于搭配覆盖率高**。不要只报“4-gram表有多少行”。

## 4. 领域证据需要的计数类型

应能从原料生成 `(cluster_id, history, next_character)`，同一去重文档簇对同一转移最多贡献1。history最多3字符，与通用模型共享BOS/EOS/UNK；只统计当前共享检索集合里的文档证据。

`n_dom(h,w)`是含该转移的文档簇数；`n_dom(h)=Σ_w n_dom(h,w)`。后者**不是含h的文档数**。E034已测到“12份文档有大将军，但后继文档计数之和49”，两种分母不能混用。

无需Qwen直接生成一张全库领域词频替代通用模型。首版算法在每视频检索后临时统计，结束释放；以后可按性能需要预存每簇转移集合。重复证据不能因多段、多次出现、转载重新加权。

## 5. 当前运行包：必须与代码字段完全一致

```
package/
  manifest.json
  model.json
  evidence.sqlite
  competitors.json
  parameters.json
```

### manifest.json

`format="tc-evidence-package-1"`；`files`逐一列出上述四个内容文件的SHA256；`frontend_sha256`绑定C++二进制；`source_files`绑定AC/读音/候选表，路径相对项目根；来源数据库SHA、构建版本和数据限制留存。加载器拒绝哈希不符和越出包目录的路径。不能换词库却继续用旧校准标记。

### model.json（算法构建器生成）

- `format="tc-mkn-1"`、`order=4`、`vocab`共享字符列表。
- `counts["4"]`为完整4阶次数；1–3阶为不同前驱的续接计数。每阶存`[[gram,count],...]`，不能把E033原始低阶次数直接改名塞进来。
- `discounts["2"/"3"/"4"]=[D1,D2,D3+]`；`discount_fallback_orders`记录数据不足时退回固定折扣的阶数。退回时仍可归一，但不能冒称折扣已充分估计。
- 每条计数为正整数，字符属于V或BOS，预测项不能为BOS。EOS/UNK必须有有效底层质量。

### evidence.sqlite（构建器从原料派生）

- `meta(key,value)`包含`format=tc-rag-1`。
- `documents(cluster_id PRIMARY KEY, source_family, domain, url, license, source_sha)`。
- `segments(id PRIMARY KEY, cluster_id, ordinal, text)`：完整汉字句段，**不重叠、不人工截句**。
- `search`为FTS5，字段tokens，rowid=segments.id；token是段内相邻二字串，支持二字实体。
- `term_docs(term PRIMARY KEY, docs)`：每个二字串的去重文档簇数，只用于选择全篇检索词，不参与新判决分数。

### competitors.json（派生，不改变权限）

`characters={汉字:[完整带调读音,...]}`；`entries=[{"word":词形,"readings":[[音节,...],...],"hot":布尔值},...]`。同词形只保留一条，完整变体去重，词长与音节数相等。执行资格不会从此文件读取，始终由C++候选出口决定。

### parameters.json（Astra负责，不是Qwen词库工作）

`classes={same:[a,β],tone:[a,β],near:[a,β]}`；`rho`是**整窗共享**背景质量；`kappa`、`alpha`、`top_h`、`retrieval_limit`、`calibrated`。当前工程初值a=0、β=1、ρ=1、κ=10、α=.01、H前30、检索50句，均**未拟合，未证明风险**。默认`calibrated=false`，普通入口KEEP；明确`--research`才允许用初值做实验。禁止为了跑出改写把calibrated自行改true。

## 6. 交付顺序与怎么验收

1. 先修完语料身份/句界/offset/去重簇，交corpus.sqlite、源清单、SHA与版本；用现有大小先验一次。
2. 再补现代通用表达、历史领域资料与品牌/人物完整读音；每类分开报，不以扩大量作为完成标准。
3. 运行适配构建器生成新目录的包；验证概率总和、文档封顶、同一证据比较、原文保护；不要覆盖build/e035_package作为旧实验输入。
4. Astra用新包重跑同一七篇、日常负例和错领域/无领域对照，区分词库收益与参数收益；Qwen不用替算法挑最好参数。

参考命令（在项目根执行）：

```
python tools/prepare_rag_package.py --source-db <交付的corpus.sqlite> --output <新包目录> --frontend build/e035/text_clean.exe
python tests/test_rag_clean.py
python tools/rag_clean.py --package <新包目录> --executable build/e035/text_clean.exe --input <原始字幕.txt> --output <诊断.json>
```

最后一条未加research时，未校准包保持原文。参数、完整命令、所有输入SHA、逐视频改对/误改/错到错、剩余错误及时间都应记录；未核对区域不能当正确负例。新日常真值继续由园长和Qwen人工流程提供，Astra不修改它。

## 7. 本版明确未解决的边界

当前C++候选出口仍保留旧的对齐距离≤2、边缘窗限制和64上限，只移除了旧频率评分对新判决的影响。删除距离限制需要另外完整对照，本轮没有无声放宽。背景词可以增加竞争，不能突破AC锁或补出整句丢失内容。

C++共用加载器当前仍读取正式frequency文件以兼容V1；新入口不使用其数值判决，但Qwen不能据此直接删除这些文件。现模型的汉字扫描范围为U+4E00–U+9FFF；扩展区汉字应在原文留存、覆盖报告中列出，不能把丢掉它们视为正确归一。

新入口是Python编排＋C++候选前端，不是已经优化完毕的纯C++推理；也没有新参数独立校准数据。Qwen交齐资料以后仍需做校准和性能验收，不能把“可以运行”称为“可以设默认”。

## 8. 已实测的问题与交付优先级依据

E035七篇开卷：V1改对145字、误改83字、错到错25字；新入口改对8字、误改0字，剩余原替换错误1913字。关闭检索也是8/0/0，七篇输出逐字相同。**目前没有RAG增益证据，不应只扩大检索库就承诺效果。**新入口使用未校准初值，仍未替代V1。

现样品通用字符表3483项，340目标都有读音，但仅304个目标的全部汉字可评分。1176窗口里147个至少一个目标缺通用字符，26个原文缺通用字符，290个竞争集合没有可执行目标（分类可重叠）。这要求补来源可查的现代语料覆盖，不能只把缺的36个目标写进训练句，也不能把历史语料直接当现代通用语料。

现包移除1121份完全重复文档，尚无可靠近重复簇。检索有资料不代表有相关搭配。验收需分别报告：原文和目标两侧的未知字、真实句界、去重后独立来源、被用于评分的具体转移；不要用“非空命中率”替代判别收益。

成本：样品包约226MB；七篇RAG流程144.02秒，无检索22.55秒，V1为18.89秒，新包一次加载另需2.42秒。加载方式不同，不能当纯算法速度倍数；但当前检索显然有成本。先交可追踪的小版本，固定参数比较收益，再决定是否扩大。详细条件与复现见`experiments/E035/README.md`。

## 9. E038更新：边界实际接入（前文v1保留作历史）

Qwen第三轮原料的来源、位置与边界由新版构建器实际消费，不再使用`work`冒充`source_family`。对具备边界字段的原料，默认生成`tc-evidence-package-2` / `tc-rag-2`；旧E033原料及显式`--legacy-boundaries`仍可生成旧包用于对照。不得编辑旧包manifest伪装成新包。

新版运行表：

- `documents(cluster_id,source_doc_id,source_family,domain,url,license,source_sha,boundary_kind)`。
- `segments(id,cluster_id,ordinal,source_seg_id,off,text,left_context,left_class,right_class,bos,eos)`。
- `source_doc_id/source_seg_id`引用原料ID，`off`为原料全文Unicode字符偏移；每个块的文字必须可以回查。
- 每块正文最多256字，不重叠；另携带同一连续汉字段前最多3字，保证长段切块不截断内部转移。人工块首尾标为`检索块边界`，不发句首/句末证据。
- 每窗仍最多检索50块，但参与领域计数的正文＋前文合计最多8192字。最后一块若被载荷截断，不发EOS；日志保留实际使用位置、字符数、边界与来源组。8192是固定工程载荷限制，不是按真值调出的判决参数。

边界规则：明确`句末标点`才支持两侧句界；现代句库文档头尾可作句界，历史文档头尾不据此发BOS/EOS。因此全篇无句读的历史原料不会凭文件结尾制造句末。换行、句内逗读、引号、数字、字母、未知符号均不强行接起来，也不充当句末；未知段首从已有短历史降阶估计。ASR输入的内部换行同样不提供句界，输入最外层头尾作为文档边界。

通用现代模型也使用这些边界，训练单位为`(连续汉字段,确认左句界,确认右句界)`，不是把每段都包在BOS/EOS中。完整数据仍供1–4阶计数；低频阈值保持2。若某字只出现在无已知前驱的片段开头，续接概率无法估计，则映射UNK并在`no_continuation_characters`逐字记录，不赋造假的正概率。训练包6字、全量包4字受此影响，详见E038。

公式及a/β/κ/ρ/α原值不变；参数文件与E037逐值相同。模型新增`boundary_policy=explicit-edges-1`，包清单增加`retrieval_policy`和已验证的`source_capabilities`。限制说明描述当前保留的限制，不再写“缺近重复簇/缺原文映射”。同簇证据计数仍封顶1次，书级`source_family`不代替文档簇投票。

新版构建入口：

```
python tools/prepare_rag_package.py --source-db build/e036_corpus/corpus_train.sqlite --output <全新目录> --frontend build/e035/text_clean.exe
```
