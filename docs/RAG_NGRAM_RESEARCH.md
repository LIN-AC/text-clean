# RAG＋N-gram：当前状态与实现研究

2026-11-10，Astra。仅阅读、代码审查与方案研究；未实现、未跑新纠错实验，未修改生产公式、词库、人工真值或园长备忘录。以下建议不是已验证收益。

## 1. 结论

建议采用“全局资料检索 + 局部字串比较 + 原文保留”的组合。RAG 在本项目先落为**检索增强判别**：查找与当前话题相关的可靠资料，为已有候选提供可追溯证据；不让大模型逐词生成改写。N-gram 是连续若干字的搭配统计，用来比较同一位置的原文与候选。二者分别回答“这段话涉及谁/什么”和“这个写法放在这里是否合适”。

必须区分两道问题：①候选之间谁更合理；②证据是否足以改掉原文。候选排第一也可能所有候选都错，KEEP（保留原文）必须参与比较。RAG 不是正确答案来源，N-gram 也不具备完整语义理解能力。

下一步最值得做的是**固定候选池的检索证据判别实验**：先检验正确候选能否排在错误候选和 KEEP 前面，以及正确原文能否继续排第一。不要同时扩词库、改拼音门槛、动态调权和更换公式，否则无法知道哪一步有效。

## 3. 代码与旧实验之间的三个边界

1. `VideoContext` 目前只是统计标题、简介、ASR中已有词的出现，且 Zipf 路径不使用它的旧 bonus；把检索资料塞进标题或简介，不能自动得到新的有效判决。
2. `DomainEvidence::log_prob_follow` 用截断计数与固定0.5平滑；当前上下文主要比较候选前两字、后两字与邻居。长度5、6且只改中间时，首尾可能完全相同，无法区分。右侧条件分母使用候选尾部，左右证据含义也不完全对称。它是搭配分数，不能直接称为校准后的“改对概率”。
3. `experiments/E031/scripts/build_ctx.py` 中先把非汉字改为空格，随后 `chars = [c for c in seg if c != ' ']` 再数邻接，会把句内标点等隔开的两边连起来；`seq`虽保留分隔却未用于计数。这是静态审查可见的构造行为，尚未测定它造成多少误改。重建语料时应显式保留边界，单独对照，不把修边界收益归功于RAG。

现有单边扣分无法救回已被静态频率淘汰的词。因此“RAG只否决”可先减少误改，但不能宣称已经解决领域冷门词召回。研究阶段应记录**硬约束通过、静态评分淘汰之前**的候选；以后若要救回这些词，必须另行证明并批准新的准入规则。

## 4. RAG 怎样具体落地

### 4.1 保存原文资料，不只保存词频表

复用E030/E031公开语料及其来源信息建立离线资料库。历史原文负责人物、事件、称谓；现代句子负责日常表达。不要混成一张无来源的大词频表。每段保存原文、规范化文本、文档ID、来源URL、版本/SHA、许可、语言风格与段落位置。词频聚合表不能还原这些内容。

按自然段/完整句切资料；约200–400字只作为初始工程配置，不是最优值。相邻分块保留同文档关系，重复转载、同卷重复引用不能当多个独立证据。现有逐字繁简映射可能改变实体，保留原始文本用于回查，不能默默覆盖。

第一版用本地字二元串/词条倒排检索，加BM25（按关键词相关性排资料）。可先用离线脚本，后接本地SQLite或C++索引，无需服务框架、网络逐窗查询或向量数据库。SQLite FTS5支持BM25，但原生trigram全文查询不匹配少于3个Unicode字符的词；“卫青”这类二字实体必须用预分词/二字串索引或专门词条索引，不能直接套默认trigram。[SQLite官方说明](https://www.sqlite.org/fts5.html#the_trigram_tokenizer)

### 4.2 全篇选资料，分段判断，当前疑点不参与自证

- 输入依旧是标题、简介、原始ASR及原有段落位置。全篇提取主题线索，段落再细分子话题，避免一篇讲历史就把所有现代口语都改成古词。
- 每个待判窗口检索时遮住原片段，同时排除该片段重复出现形成的自证信号；使用标题、周围未改文字及其他段落线索。没有可靠主题线索就允许检索弃权。
- 用这个**不含候选答案的查询**取一份共享证据集合，原文、所有候选都在同一集合里比较。候选名称检索可用于查身份，但不能把“搜了卫青，所以查到卫青”直接当优势。
- 保留检索分数、原文证据、独立文档数、出处与冲突项；检索分数只用于挑资料，不当纠错置信度。
- 比较的是“候选是否与未改的主题线索在同一资料段中相关”，不能只数候选出现次数。上下文若同时谈汉武帝和匈奴，卫青资料可构成支持；这只是说明性例子，不是硬编码规则或新实测。
- 零命中表示未知，不表示原文错；只查到一个常见人名也不构成修改许可。资料矛盾、原文同样受支持或候选差距很小时保留原文。

知识只证明“现实中可能如此”，不能证明说话人实际说了什么。即使原文与史实冲突，也不得借RAG替说话人纠正史实；最终仍受ASR拼音范围约束。

## 5. N-gram 怎样比较整个候选

第一版研究字符4-gram：以连续4字以内的历史估计下一字概率；用降阶平滑处理没见过的组合。使用保留句界的现代语料建立通用模型，历史语料单独保存。不得为某候选只收集含该词的搭配，导致KEEP一侧天然查不到。

给同一原句分别放入原文与候选，只累计**替换导致改变的概率项**：覆盖所有改动字和受其影响的后面最多3字。这样既看到长词中间，又看到右侧搭配；句内其他完全相同项抵消，不需要把整篇塞进语言模型。N-gram自身只有有限长度，所谓“全局”来自RAG选资料，不是把N设得无限大。

原文与候选统一分词单位、句界、未知字处理和相同上下文范围；缺字或证据太少标记弃权。通用模型保留为底座，少量检索段不能独立训练一个可信模型。检索段的局部计数只能作为受支持量约束的适配证据，与通用统计分开记录；先不设动态权重、更不覆盖通用词频。

KenLM提供N-gram模型估计与modified Kneser–Ney平滑，可作离线对照，输入先按字符分开。是否接入正式C++取决于模型体积、Windows构建与速度测量，本轮不承诺性能。[作者文档](https://kheafield.com/code/kenlm/estimation/)

“RAG支持”和“N-gram支持”常来自同一批文字，不能当作两个独立概率直接相乘。先分别输出可解释证据及二者联合排序结果，验证增量价值，再讨论新判决方式。

## 6. 在现有四段流程中的位置

AC保护 → 窗口/拼音候选及硬约束 → 原有评分＋独立检索/搭配证据比较 → 候选与KEEP竞争。

检索在视频开始时批量准备、段落级缓存；不在每个字窗里发网络请求。拟议最小接口为“视频资料准备”和“按原文偏移比较候选”，返回支持/反对/未知、文档出处、搭配差及弃权原因。静态词库对象继续复用，视频结束释放临时证据。

先在实验目录做旁路观察，不直接替换现有判决；要测最终效果必须完整重跑窗口竞争，因为新排序会影响重叠窗口，不能只事后筛现有编辑。候选池外、长度不符、读音硬门被拦的错误单独记录，本轮方案不承诺检索能自动修复它们。

若将来需要从资料发现新词，先记录为建议并走已有词库审批流程，不让RAG绕过启用状态、AC或读音约束直接写字。正向证据改变修改准入另作实验，保持当前默认公式不动。

## 7. 临时记忆与Whisper p

视频内临时知识先是“出处可查的证据缓存”，不是“程序改过就算学对”。原始ASR重复出现只代表一致性，多个错误重复也可能一致；本轮输出不回写训练、词频或同轮上下文。未来两遍处理也要冻结第一遍证据、逐处核对，不能因一个位置通过就全局替换同形词。

园长提出的“找最低p句子核查”适合安排检查顺序。p是识别模型置信信息，token并非一一对应汉字；最低p句没错，**不能推断其他句都对**，更不能给全篇高置信锁。高p错误也应进入抽查。RAG＋N-gram首轮固定不用p和动态权重，后续才能测它们提供多少独立收益，避免同时引入三种自我强化。

## 8. 建议的唯一下一轮实验与验收

**命题：使用不含待纠错片段的上下文检索，能否更准确地区分原文、正确候选和错误候选？**

固定当前340目标词、真值、读音、AC、拼音限制与原公式。使用同一批硬约束通过的窗口，包含原本正确的位置，不能只挑漏纠错字。语料版本提前冻结，排除本项目字幕、真值及其转载；公共原典与讲述内容相似不等于泄漏，需记录近重复检查结果。

| 对照 | 回答的问题 |
|---|---|
| 零操作、当前V1 | 有无绝对收益及相对当前收益 |
| 只有改进N-gram，无检索 | 完整搭配比较本身的作用 |
| 只有检索证据，无新N-gram | 全局资料有没有独立判别力 |
| 检索＋N-gram | 两者合用是否优于各自单用 |
| 错领域/随机资料替代正确检索 | 是否真的依赖相关证据，而非又一个词频偏置 |

先报告共享候选集的正确排名、KEEP排名、相关资料命中与弃权，再按预先固定的规则完整重跑竞争；研究用规则不自动成为生产规则。同时报告与V1、零操作、E027三档的差值，并按E027要求给出首音节保护开/关的诊断对照，不据此取消保护。

判断标准不只看排名：在**保留同样多正确修复**时少误改，或在**相同误改预算**下多修好；还须报错到错、漏改、每篇结果、候选不可达、检索缺证据、否决及竞争损失。保留完整门槛曲线，不在同一七篇上挑最佳点宣称验证。现有145/82/25/1961只是当前开卷参考，尚无新系统结果。

历史七篇可验证机制；其中非历史视频分开报，仍属于开卷。优先核实已有日常ASR有没有未参与建库且人工完成的真值；没有就明确缺少独立验证，不要求大规模新增标注，也不把未核对文本当正确。用于调规则的视频与最后验收视频不得重合。

性能须记录冷启动、热启动、每视频检索耗时、候选比较耗时、峰值内存、索引/模型磁盘体积与缓存命中。N-gram每个候选通常只需局部查询；RAG是新增主要成本。当前未测，不能承诺保持旧吞吐。

负面结果同样决定方向：①相关资料命中但候选仍选错，说明词面共现不足以判别；②仅历史专项提升而日常误改上升，说明领域偏置未解；③只能靠大量弃权少误改且正确修复同步大降，说明没有独立增益；④无关资料效果一样，说明没有真正用到检索。出现这些结果应停止加参数，检查证据表达；不能靠扩候选池掩盖失败。

暂不做：大模型逐词改写、整句补写、自动扩正式候选池、取消拼音保护、候选专属检索结果直接加分、纠错结果即时学习、单看低p决定全篇正确、一次引入动态λ/μ和Claude新公式。
