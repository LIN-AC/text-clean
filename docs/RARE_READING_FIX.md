## 触发链路

1. 现有最长分词把短句切为：`这个 / 颜色 / 要略 / 微深(未知) / 一点`。词频表同时有“要略”和“略微”，贪心选择前者使“微深”成为普通未知窗口，并非必须依赖P2新增的边缘窗口。
2. 字符拼音表中：深=`shen1`，信=`xin4,shen1`。动作词表为微信指定的是 `wei xin`。
3. 旧实现为候选收集规范词每个字符的全部读音，忽略了词级基音约束；因此错误地认为“微信”可读为 `wei1 shen1`。
4. 检索、声调距离、近音门槛共享这组过宽读音，结果为零距离。原窗口频率为0，目标词频3，得分为 `ln(4)-0.70≈0.686294>0`，即使没有视频上下文也放行。

此分数是启发式差分分数，不是校准后的正确率。仅增加修改阈值或禁用新的P2窗口都没有解决词级读音错误。

## 实现修复

`TextCleaner::Impl::build` 构造候选读音时，以 `LexiconEntry::pinyin[k]` 为约束，过滤掉字符字典中其他基音的读音；同基音不同声调读音仍保留。过滤后的 `entry_toned` 同时用于：

- 候选倒排索引和首音节集合；
- 对应声调距离；
- 逐位置近音硬限制。

若字典缺失声明基音，按既有显式拼音回退原则使用该基音、未知声调0，不混入其他基音。输入侧仍保留多音字可能读音。没有全局删除“信”的异读，也没有粗暴地只取所有字符的首读音，因此词级声明 `yin hang` 的“银行”和输入侧“行”的其他合法读音继续可用。
