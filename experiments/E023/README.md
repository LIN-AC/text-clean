## 六、结论：退步的主因不是 Zipf 单位，而是"缺证据即弃权"这条策略

1. **主因（81% 的召回损失）**：新规则把"原文在词频表里查不到"从旧口径的**给满分额**（`fO=0 → logR=ln(1+fC)`，正是 ASR 错字最常见的形态）改成**整窗弃权**。漏斗上这道门拦掉 9,680 个窗口，counts 模式这道门是 0。
2. **单位换算本身不是问题**：消融 C 全程用 Zipf 尺度（原文缺证据时按字频独立估计 `Σzipf(字) − 9×(n−1)`），改对字 230、总距离 1934，几乎追平 counts 的 1927。**说明换算式 `2.302585×(zipfC−zipfO)` 可用，坏在缺失处理。**
3. **次因（14%）是通用语料与领域热词的固有冲突**：82/109 个有证据配对里"错词反而更常见"，靠换库或调阈值解决不了，只能靠词表侧（候选覆盖、别名权威化）或上下文证据。
4. **数据缺口是客观存在**：115/336 目标词、234/357 别称在 wordfreq 里没有正 Zipf。`sources=none` 的 66,872 行 + `ours` 的 18 行按实现约定不参与评分。
5. **实现核对结论**：`2.302585` 系数正确；缺失值用 `optional` 而非 0 的做法正确且必要（wordfreq 的默认 0 是"低于返回下限"，不是观测到的零概率）；**领域列 `ours_count` 没有接入评分是正确决定**——它由 `asr/*.gt.txt` 统计而来，就是这 7 篇的答案，接入即泄漏（已核 `dictionary_bundle.cpp` 从不读 `ours_*`）。
6. **发现一个实现留白（非缺陷但影响判断）**：`data/frequency/char_freq.tsv` 被读进 `DictionaryBundle.char_frequency` 后**没有任何消费者**（Zipf 模式下 `CharFrequency` 仍是旧次数表，`main.cpp:402` 明确禁止混用）。所以"旧字符频率补偿"目前**只能靠新增读取路径实现**，不是打开某个开关。

## 七、最小修改建议（等你批准再动源码，本轮没做）

1. **M1（对应消融 C，最小且最有效）**：把 `text_cleaner.cpp` 缺原文证据的 `continue` 换成"用字频 Zipf 估计"：
   `ZipfO_est = Σ Zipf(每个字) − 9×(长度−1)`，只在原文缺词级证据时使用；两侧字都缺才弃权。
   预期效果（本次实测）：改对字 20→230，总距离 2090→1934，误改字 86→140。
2. **M2（压掉 M1 带来的误改涨 43~54 字）**：给"缺证据"的额度加常数上限，等价恢复旧式 `+1 平滑` 的隐性封顶：
   `ZipfO_est = max(字符独立估计, ZipfC − K)`，K=1.5 约等于旧式 `ln(1+fC)` 能给的最大额度。
   建议 K∈{1, 1.5, 2, 3} 扫一遍距离/误改曲线再定值，**不要先调 λ/μ**（E3/D-4 已证调阈值无效）。
3. **M3（数据侧，不动公式）**：115 个无词频证据的启用目标词，现在"看似启用实则永不触发"。要么把这类配对暂时改 `status=0` 并在报告里单列漏改量，要么补一份不泄漏的词频来源。**不能用 `ours_count` 补**（真值泄漏）。
4. **M4（工程，避免每轮复制源码）**：把缺证据处理做成显式三态参数 `--missing-evidence=veto|char|capped`（默认 veto 保持现状），消融与生产同源、无需 probe 副本；同时把 `char_freq.tsv` 的 Zipf 读取路径正式补进加载器，让"字频表读了没人用"这件事消失。
