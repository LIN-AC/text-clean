调到 3 就把绝大多数修复打掉，说明这个下界真的接在流水线里；**"1 和 2 完全相同"是真结果，不是开关失效**。（中途试过用 `--lexicon` 造合成单字用例来验证，结果连双字用例都不触发——该路径下正式候选池与 AC 仍来自 bundle，测试装置无效，已放弃，改用上面的下界扫描验证。）

## 三、为什么是 0（两道硬卡，缺一不可）

1. **候选池里没有单字目标词。** 340 个启用目标词长度全是 2–6 字，长度 1 的 **0 个**。而替换要求"目标词长度 = 窗口长度"，所以长度 1 的窗口根本找不到任何候选。
2. **词频表里没有单字条目。** `word_freq.tsv` 的单字条目 **0 条**；评分只看词级表，目标词查不到证据就直接弃权。所以即使往池里加了单字目标，也一样会被这一条挡掉——那需要动评分的证据来源，属词库与公式变更，未批准前没做。

也就是说：**只改窗口下限这条路本身走不通，必须同时改候选池和频率证据来源**，那已经是两项需要园长批准的变更。

## 四、就算全部改通，单字纠错的天花板也很低（离线估算，未改流水线）

对 640 个"没修好的严格同音单字错误"，用最朴素的规则"同一个读音里挑字频最高的字"来改：

* 改对 **115 个（18.0%）**
* 改回原来的错字（等于白改）**224 个（35.0%）**
* 改成第三个字（制造新错）**301 个（47.0%）**

样本：`枪→应作"腔"却选"将"`、`评→应作"屏"却选"平"`、`祝→应作"铸"却选"住"`、`事→应作"示"却选"是"`。

结论：单字同音错的主体不是"能靠频率挑出来"的，近一半会改成另一个错字。**不建议把单字纠错当成下一步方向**；真要推进，需要的是上下文/词组级别的证据，而不是把窗口切到单字。
