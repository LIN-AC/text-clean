# E031｜上下文评分：现代语料 × 锚点跨度 × 单边否决（2026-11-08，实验分支 exp/e031-context-scoring）

园长判断：瓶颈不是词库大小，而是**程序不知道该改哪个更正确**。本轮据此优先做上下文评分。全部来源、许可、SHA 见 `results/manifest.json`。

## 一、语料

* 现代：**Tatoeba 中文句库** `cmn_sentences.tsv.bz2`（CC-BY 2.0 FR，SHA `262a48cacb7693f6`），89,289 句 / **916,062 汉字**，繁→简用仓库内 CC-CEDICT 逐字映射。
* 尝试过并放弃：中文维基新闻（zh.wikinews，18,686 篇，CC BY 2.5）——`prop=extracts` 对绝大多数页面返回空正文，60 篇里只有 2 篇有正文，拿不到可用体量；维基文库文言语料不属于现代句式。
* 文言对照：沿用 E030 的 713 万字历史语料。
* 建表原则（重要）：n-gram 表**按出现次数阈值裁剪，不按候选词裁剪**。若只保留含候选词的串，原文一侧的计数会被系统性压低，等于偏袒目标词，违反"片段不可自证"。

## 四、四条结论

1. **上下文必须"只许否决，不许放行"**。双边上下文在权重 1.0 时是灾难：近音(d≥1)编辑从 81 涨到 131–134，纯改坏编辑从 54 涨到 103–107，总错误量比不纠错还差 54–67。改成单边后同样的权重反而把近音编辑压到 61–69、误改字降到 70–82，**总错误量 1961–1964，是全场最稳的一族**。园长的判断在这里得到直接验证：程序缺的不是更多改写理由，而是"什么时候不该改"的判据。
2. **锚点跨度 2 优于跨度 1**。跨度 1（只看单个邻字）在现代语料上改对 +66 但误改 +97（S4，净亏 31）；跨度 2 几乎不增加改写，只减少错改（V1/W2）。信息量太短的上下文只会放大常见词偏好。
3. **上下文与领域词频是互补的，不互相替代**。卫青族在纯上下文臂一律 1/6（上下文不知道卫青是个人名），只有历史词频臂才 6/6。叠加后 W2 同时拿到"6/6 冷门词修复 + 205 改对字"，总错误量 1972；想要更少的误改就用 W5（1946，误改 56），代价是卫青族掉到 4/6、改对字 134 —— **刹车踩得狠，会把对的也刹住**。
4. **历史词频洪水能被单边上下文部分治理**：E030 的 gap=1.5 是 283/441/2182；加单边上下文后 283/418/2159，只降 23 字，仍然不可用；真正可用的是把 gap 收到 0.45（W1，总错误量与控制臂持平但改对 +60、卫青 6/6），再加单边上下文（W2）净赚 5 字且卫青保持 6/6。

## 五、口径提示（避免和 E030 混用）

* 本轮所有臂都跑在同一份 E031 上下文表上；E030 的 X2（158/104/1970）用的是按整篇连读建的 pairs 表，本轮 S1（156/104/1972）是按 400 字分块建的表，**跨块邻接被切断**，两者不应视为同一实验的重复测量，差 2 字属表构造差异。
* 编辑分类为三类：AC 精确 / 拼音同音(d=0) / 近音(d≥1)。E030 曾把 fuzzy 混进"AC 精确"，本轮已更正（`近音(d≥1)` 一列才是上下文真正影响的部分）。
* 卫青族按**词对**计数（同词对多次出现只算一组），与 E030 一致；E031 早期版本按出现次数计数导致出现"15"这种误导性数字，已改。
* 权重与 gap 的多个取值只是画曲线，七篇全开卷，**不得把最优点当调好的参数**；合并表与"纯上下文"臂的净收益都很小（5–16 字），已在噪声量级附近，需要独立真值复核。

## 六、建议下一步（需批准）

1. 把**单边上下文**做正式化：先只作为"减分/否决"项接入，配 2 字锚点与最低支持次数；这一项单独就能给出 1961（−16 字）。
2. 找一份**足够大的现代语料**（目标 ≥3,000 万汉字，现代书面/口语，许可可商用或明确仅研究用）。Tatoeba 只有 92 万字，跨度 2 的锚点大量落在"支持不足→弃权"，V1 的收益是被数据量压住的。
3. 上下文与历史词频的叠加方式改成**分档**：历史词频只在"原文在通用域与历史域都查无"时给有上限的加分（W1 的 0.45 档已给出证据），上下文只否决。这两条合起来是 W2/W5 的方向。
