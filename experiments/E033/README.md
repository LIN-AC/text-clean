## 四、第三步：二字实体检索能不能用（`experiments/E033/scripts/probe_kb.py`）

四个已知疑难位点（原始 ASR 里的别名 → 真值目标词），三种查询形式对照：

| 位点 | 目标词在库段数 | Q1 遮住疑点只查上下文，top5 含目标词 | Q2 直接查别名 | Q3 无关现代话查历史库 | Q1c AND 最稀有两串 | Q1d NEAR60 |
|---|---|---|---|---|---|---|
| 魏清→卫青 | 48 | 0/5 | 0 条 | 5 条（含目标 0） | 0 条 | 0 条 |
| 桑红阳→桑弘羊 | 20 | 0/5 | 5 条 | 5 条（含目标 0） | 0 条 | 0 条 |
| 填富→田赋 | 95 | 0/5 | 0 条 | 5 条（含目标 0） | 0 条 | 0 条 |
| 现关→县官 | 199 | 0/5 | 0 条 | 5 条（含目标 0） | 0 条 | 0 条 |

耗时：单次查询 12.9–19.9ms（中位 16.6ms，冷连接，235MB 库）。

**判据 0/4 命中**——这就是 Astra 预判的失败模式①：话题相关的资料取回来了（`桑红阳` 一例的 top3 就是《史记·平准书》"大农上盐铁丞孔仅咸阳言山海天地之藏…"、"以东郭咸阳孔仅为大农丞领盐铁事桑羊以计算用事"），**但目标词形没进 top5**。用"目标词是否出现在检索结果里"当支持信号，在这个配置下等于永远不支持。

顺带查出的三个技术问题（都已量化，下一轮必须先修，否则测什么都是假的）：
1. **250 字切块不重叠会丢边界串**：卫青原文 58 次 → 索引只 48 段，县官 226→199，田赋 105→95，约 12%~16% 的实体被切没。改法：切块加 8~16 字重叠，或按卷整篇入索引 + 段级定位。
2. **三字以上词不是被索引的 token**：单查 `"桑弘羊"` 得 0，改用 `"桑弘" AND "弘羊"` 得 20/20 ✓。词典式查询必须按词长展开成 token 链。
3. **OR 查询没有弃权**：完全无关的现代话在历史库里照样返回 5 条。必须加分数下限 + 独立文档数下限，并允许"未知"，否则"检索命中"这三个字没有意义。
4. 另外，"最稀有两个二字串"选出来的全是 ASR 错字串（`压声`、`吱压`、`台推`、`富生`、`快陷`…），说明**查询词不能从含错原文里直接取**，得用标题/简介/未被质疑且多模型一致的文字，或按词频带过滤（太稀有的当噪声丢掉）。

**结论：链路通了，证据强度还没通。** 在解决上面四点之前，不把检索接进任何判决通道，也不申请改生产。

## 五、古籍异写/简称归一（园长指示"先做异写归一，解决桑羊的问题"）

**先说做不到的那半句**：`桑羊` 与 `桑弘羊` 在我们这批古籍里**没有任何共现证据**——桑羊只见于《史記集解》《後漢書》，桑弘羊只见于《漢書》《漢書顏師古註》，书名交集为空、卷级交集为 0。任何"从语料自证"的规则都不该收下它，硬收就是我编的。外部权威别名源试过两次：zh.wikipedia 的重定向查询通、但正文/内容 API 本机不可达（code=000），且"桑羊"本身不是条目名。所以这一对**留给园长决定**：要么批准新增一个可署名的别名数据源，要么由人工审定一张带出处的异写表进词库。

**做到的那半句**：自动派生规则不手写词表，全部可审计（`experiments/E033/scripts/alias_forms.py` → `build/e033_kb/alias_forms.tsv`）：
- 形态：变体必须是目标词的保序真子序列，长度 ≥2；
- 稀有：df(变体) ≤ 2×df(目标)，把"司马"这种能独立成词的高频串挡在外面；
- 同书：变体与目标至少共享一部书名。
75 个 ≥3 字目标词派生出 **20 条异写/简称，覆盖 12 个目标词**，其中 `桑弘羊 ← 弘羊/桑弘`、`霍去病 ← 霍去/去病`、`司马迁 ← 马迁`（`司马` 被稀有度规则正确拒收）。

接进判决后的效果（`retrieve.py`，可用 `--no-alias` 整体关掉做消融）：桑弘羊那例的独立文档数从 0 → **2**，判定从"未知"变成"支持改"，四个手工位点变成 **3 支持 / 1 弃权 / 0 误判**。但紧接着第五臂说明这个"支持"值多少钱。

## 六、第五臂：错领域与随机资料的假阳性对照（结论是坏消息）

位点自动定位，不挑好的：候选表启用行里"别名出现在原始 ASR、目标词出现在人工真值、长度相同"的配对，七篇共 **338 个位点**（历史片 289、现代片 49）。同一批位点、同一套阈值，只换资料来源（`control_arms.py`）：

| 资料来源 | 判"支持改"的位点数 | 比例 |
|---|---|---|
| 正确领域检索 | 36 / 338 | **11%** |
| 错领域检索（历史位点查现代库，反之） | 2 / 338 | 1% |
| 随机抽 300 段（3 个固定种子） | 59 / 1014 | **6%** |

怎么读：
1. 错领域只有 1%，说明检索确实在用主题相关性，不是纯词频偏置 ✓；
2. **但随机抽样就有 6%**——正确检索的净增益只有 **11% − 6% = 5 个百分点**，"支持"里有一半上下不需要检索也能得到；
3. 支持率本身很低：338 个位点里 302 个弃权（可靠查询词不足 3 个，或目标词的独立文档数 <2）；
4. 上一节那四个手工挑的位点得到"3/4 支持"，放到 338 位点全量里就是 11%——**再次证明挑案例会把结论抬到不可信的高度**，以后所有"支持率"必须与随机基线成对报告。

判定：**这条检索证据通路按当前配置不构成接入判决的理由**。要往下走必须先解决查询（用书名/标题这类真主题线索、要求 AND 共现而不是 OR 命中）和语料规模，并把"相对随机基线的净增益"写进验收指标。

## 七、④ 字符 4-gram 底座（建成，测出负面结果）

`build_lm.py` 产出 `build/e033_lm/{modern,history}/counts{1..4}.tsv` + `inputs.json`（语料 SHA、边界与平滑口径）：现代 916,062 字（4-gram 行 80,811，min_count=2，建库 1.6 秒，3.4MB）；历史 7,136,396 字（4-gram 行 211,443，min_count=3，14.5 秒，17MB）。边界与本轮换表一致（非汉字是边界，句首补 `^^^`），平滑用 stupid backoff α=0.4。

成对比较（同一段真实上下文里放目标词形 vs 放表内错误别名，只累计替换影响的转移；上下文取自人工真值，所以这只测"表本身有没有区分力"，不是生产表现）：

| 底座 | 上下文来源 | 可测次数 | 目标词形胜 | 别名胜 |
|---|---|---|---|---|
| 现代（92 万字） | 历史片词对 | 493 | 36.3% | **63.7%** |
| 现代（92 万字） | 现代片词对 | 124 | 44.4% | **55.6%** |
| 历史（713 万字） | 历史片词对 | 493 | **70.0%** | 29.8% |
| 历史（713 万字） | 现代片词对 | 124 | 43.5% | 55.6% |

关键读数：
1. 现代底座连在**自己领域**的词对上都只有 44.4% 胜——低于对半，等于**反向证据**。机制可解释：错误别名由常见字组成，字符级模型把"常见字组合"打高分，这是**字频偏置不是搭配知识**。
2. 历史底座在历史词对上 70.0% ✓ 有判别力，跨到现代词对就掉到 43.5%（领域错配，符合预期）。
3. 之前担心"92 万字导致大量弃权"，实测这张按字符的表**弃权率只有 4.0%（现代）/ 2.0%（历史）**——问题不是查不到，而是查到的东西没区分力。所以"扩大语料"之前，得先解决字频偏置（候选方案：只在同长度同位置的成对比较里用、或改为词级搭配、或对常见字做归一），单加数据量不解决方向性错误。
4. 重点词对逐对结果（历史底座）：轻徭薄赋←清姚伯父 3/3、桑弘羊←丧红阳 3/3、田赋←填富 3/3、卫青←魏清 2/2、豪强←刨墙 3/3 都对；**贞观←真关 0/1、赈济←政绩 0/2 判反**，不是全对。
