## 二、第一步：只改"上下文表是否保留句内边界"

3. 不要把"修句界"当成待领的分数。判断依据只有 A2 这一条对照，噪声级别的结果不引申。

## 三、第二步：带出处的资料库（`experiments/E033/scripts/build_kb.py`）

SQLite FTS5，产物 `build/e033_kb/kb.sqlite`（235,073,536 字节，SHA `8d19fb93…`，建库 22.7 秒）：

| 表 | 内容 |
|---|---|
| `docs` | doc_id、**domain（历史/现代分库标记，不混库）**、书名、页名、来源 URL、许可、抓取时间、源文件 SHA256、段数 |
| `segs` | seg_id、doc_id、段序号、规范化文本（非汉字一律变空格，**边界保留**）、字数 |
| `kb` | FTS5 倒排：每段的"单字 + 相邻二字串"token 流 |
| `meta` | 建库时间与三份输入的 SHA |

规模：文档 90,184（历史 1,014 卷 / 现代 89,170 句），段 118,108。

两条配套统计：
- **重复段 1,028 条**（同一段文字出现在多份文档里，多为四库全书书头套话）。按 Astra 要求，这类重复不能当多个独立证据——检索时必须按 doc 去重计数。
- **泄漏检查：本项目七篇真值 + 原始 ASR 的 3,094 个 12 字窗口，在这份资料库里 0 命中** → 语料没被答案污染。已知局限：窗口取自规范化文本且要求 12 字连续，覆盖偏保守，④ 阶段要用更强口径复核。

## 四、第三步：二字实体检索能不能用（`experiments/E033/scripts/probe_kb.py`）

四个已知疑难位点（原始 ASR 里的别名 → 真值目标词），三种查询形式对照：

| 位点 | 目标词在库段数 | Q1 遮住疑点只查上下文，top5 含目标词 | Q2 直接查别名 | Q3 无关现代话查历史库 | Q1c AND 最稀有两串 | Q1d NEAR60 |
|---|---|---|---|---|---|---|
| 魏清→卫青 | 48 | 0/5 | 0 条 | 5 条（含目标 0） | 0 条 | 0 条 |
| 桑红阳→桑弘羊 | 20 | 0/5 | 5 条 | 5 条（含目标 0） | 0 条 | 0 条 |
| 填富→田赋 | 95 | 0/5 | 0 条 | 5 条（含目标 0） | 0 条 | 0 条 |
| 现关→县官 | 199 | 0/5 | 0 条 | 5 条（含目标 0） | 0 条 | 0 条 |

耗时：单次查询 12.9–19.9ms（中位 16.6ms，冷连接，235MB 库）。

**判据 0/4 命中**——这就是 Astra 预判的失败模式①：话题相关的资料取回来了（`桑红阳` 一例的 top3 就是《史记·平准书》"大农上盐铁丞孔仅咸阳言山海天地之藏…"、"以东郭咸阳孔仅为大农丞领盐铁事桑羊以计算用事"），**但目标词形没进 top5**。用"目标词是否出现在检索结果里"当支持信号，在这个配置下等于永远不支持。

顺带查出的三个技术问题（都已量化，下一轮必须先修，否则测什么都是假的）：
1. **250 字切块不重叠会丢边界串**：卫青原文 58 次 → 索引只 48 段，县官 226→199，田赋 105→95，约 12%~16% 的实体被切没。改法：切块加 8~16 字重叠，或按卷整篇入索引 + 段级定位。
2. **三字以上词不是被索引的 token**：单查 `"桑弘羊"` 得 0，改用 `"桑弘" AND "弘羊"` 得 20/20 ✓。词典式查询必须按词长展开成 token 链。
3. **OR 查询没有弃权**：完全无关的现代话在历史库里照样返回 5 条。必须加分数下限 + 独立文档数下限，并允许"未知"，否则"检索命中"这三个字没有意义。
4. 另外，"最稀有两个二字串"选出来的全是 ASR 错字串（`压声`、`吱压`、`台推`、`富生`、`快陷`…），说明**查询词不能从含错原文里直接取**，得用标题/简介/未被质疑且多模型一致的文字，或按词频带过滤（太稀有的当噪声丢掉）。

**结论：链路通了，证据强度还没通。** 在解决上面四点之前，不把检索接进任何判决通道，也不申请改生产。

## 四点五、修复轮（2026-11-10 园长批准"按顺序修复"之后）

四个坑逐个修，修完立刻复测同一批位点，**没有顺手改判决规则以外的东西**。

| 坑 | 修法 | 复测结果 |
|---|---|---|
| (a) 250 字切块不留重叠，实体被切断 | `build_kb.py` 改 STEP=250/OVERLAP=24，并放开卷尾短段（min 6 字）；segs 加 `off` 列 | 卫青原文 58 次**逐条 LIKE 复核全部入库**；FTS 段级命中 51（同段多次只算一次，不是丢数据）；库 121,153 段 / 256MB / 建库 11.8 秒 |
| (b) 三字以上词不是被索引的 token | 查询侧按词长展开：2 字用二字串 token，≥3 字用单字块相邻短语（`"桑 弘 羊"`） | 桑弘羊由 0 段变 19 段（原文 20 次）✓ |
| (c) OR 查询永远有结果，等于没有弃权 | 两阶段：先取 K=300 段同主题资料，段数 < 20 直接弃权；再数目标词/别名各自出现在多少份**独立文档**里，需 ≥MIN_DOCS=2 且 ≥2×别名文档数才算支持 | 对照实验：无关现代话（今天/中午/项目）查历史库仍返回 225 段 → 证明没有阈值就必须弃权 |
| (d) 查询词不能从含错原文里挑 | 只取 **whisper 与 FunASR 两个模型都写成同一个字**的连续片段（≥6 字），再按资料库文档频率带 (3, 5000) 过滤；疑点本身及两侧各 90 字内取词 | 修复前"最稀有二字串"选出来的是 `压声 吱压 台推 富生 快陷`；修复后同一位点选出 `汉武 武帝 盐铁 财政 工具 货币 司马 马迁` 这类真主题词 |

**同一批四个位点，修复前后的判决对比**（`retrieve.py`，输出 `results/retrieve_fixed.json`）：

| 位点 | 修复前：top5 含目标词 | 修复后：目标词独立文档 / 别名独立文档 | 修复后判定 |
|---|---|---|---|
| 魏清→卫青 | 0/5 | 3 / 0 | **支持改** |
| 桑红阳→桑弘羊 | 0/5 | 0 / 0 | 未知（弃权；库里 19 段有"桑弘羊"，但这批检索结果里是"桑羊"等异写，词形对不上） |
| 填富→田赋 | 0/5 | 1 / 0 | 未知（独立文档不足 2 份） |
| 现关→县官 | 0/5 | 6 / 0 | **支持改** |

判据从 0/4 命中变成 **2/4 支持、2/4 明确弃权、0 例误判为反对**。两个弃权案例说明弃权通道是真在起作用（不是全弃权也不是全自动手）；桑弘羊那例暴露出下一个必须处理的问题：**古籍异写（桑羊／桑弘羊）会让"词形一致"判定失效**，属于异体/简称归一问题，不是检索失败。

**基线变动（园长批准换表带来的）**：生产默认从 145/82/25/**1961** 变成 145/83/25/**1962**（改对不变，多 1 处误改：`BV1sxxX64E4E` 第 980 字「以同为敬」被改成「一同为敬」）。`run_arms.py` 已把两档都写成断言：A0=新默认，A1=旧口径表（`--context-dir build/e033_ctx_repro`，钉 1961），A2=关上下文（钉 1977）。工程测试 ctest **24/24 通过**。
