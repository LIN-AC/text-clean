## 三、尚未通过的接入与边界项目

**最高优先级：我方消费者的左上下文正则跨换行。** `tools/rag_clean.py`使用`re.search('[一-鿿]*$', text[:b])`；Python的`$`也能匹配末尾换行之前，所以位于下一cue开头的窗口可能读取上一cue的结尾，右侧却仍按换行截断。独立倒序逐字扫描对照发现，训练包1174个窗口中285个不一致，涉及2次已执行修改。例：`据史书记载\n魏清获取病…`的候选左上下文被取成`据史书记载`，而非当前连续汉字段的空前缀。

这不是Qwen数据造成的。本轮没有静默修正后继续把两组成绩混报，也没有将其解释为有意跨ASR段建模。结果保留为当前版本的诊断；修正需完整重跑。复现见`results/trace_details.json`和`scripts/trace_details.py`。

1. **新边界标签没有进入运行包。** 两包segments字段仍只有`id/cluster_id/ordinal/text`，没有原文offset、左右边界类别。消费者仍将每段视作完整汉字句段，给各段加句首/句末；原料多了字段尚不能改变这一行为。来源组与限制说明的接入仍未完成，属于Astra消费者侧的后续工作。
2. **类别与句末标记冲突32处。** 历史右端19处、左端13处：ASCII感叹号/问号在类别字段中是“句末标点”，但`*_is_stop=0`。各标记单独符合各自建库代码，却不能让消费者得到一致答案，应先统一规则。
3. **“换行或空白”标签过宽。** 右端该标签共有109603处，其中65365处紧邻字符实际不是常见空白，而是引号、书名号、模板符、数字、字母等。例如模板`{{SK note...}}`仍有残留。这里包含真实标点和标记残留，不能把整类当作可跨越的排版换行，更不能直接拼接。
4. **无句读的历史文档实际608份，不是146份。** 数据逐篇标记与实测一致；除了史記集解125、後漢書補逸21，另有後漢書130、明史331、漢書1份不含所检查的中文句末标点。报告的“只有两部书共146卷”需收窄为书级概括，处理时必须以文档/位置证据为准。
5. **原料统计仍需标明字符范围。** `verify_v2`所谓汉字数实际包含所有非空格字符，可能包含扩展字和其他被保留字符。本轮明确基本汉字范围U+4E00–U+9FFF：现代915996字、历史7133866字；不等于报告916071/7152584，也不等于含空白的9181494字符。原文完整留存通过，不代表所有这些字符都参与模型。

这些问题不推翻已通过的簇隔离和映射结果，但意味着只能接收为**可追查的实验原料**，不能验收为边界证据已正确进入新模型的完成版本。
