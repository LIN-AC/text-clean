## 二、复核方法

- `scripts/audit_candidates.py`：结构（字段数、status、启用行别名必须与目标词等长且全汉字——这是
  `dictionary_bundle.cpp` 会抛错的硬条件）、拼音按装配器同一规则 `[a-zv:]+[0-5]` 切分并与读音表
  `data/pronunciation/pronunciation.tsv` 比对、别名自指、整行重复、同一别名映射多个启用目标、
  单字启用目标（`min_syllables_for_exact_pinyin=2` 下结构不可达）、词表证据覆盖。
  结果 → `results/candidate_audit.json`。
- `scripts/v1_impact.py`：把 `data/` 用**硬链接**镜像成两份（不复制、不触碰工作文件），
  分别放当前表与 git HEAD 表，同一二进制 `build/e035/text_clean.exe --no-index-cache`、
  同一 `experiments/E024/scripts/align_lib.py` 口径跑七篇，逐条比对编辑差值并归因。
  结果 → `results/v1_impact.json`。跑完删除镜像，工作文件哈希复核未变。

装配器读音优先级（决定了两类缺陷的严重性不同）：`DictionaryBundle::load` 先查词级读音表，
命中就**忽略**表内 `pinyin` 列；查不到才用 `pronunciations(行内拼音, 字数)`，且**音节数对不上字数会整条读音被丢弃**。

## 四、语义裁定：`耕赋` vs `更赋`（结论已落在二·五）

真值里**两个词形都出现过**：位点 8344 处 ASR"更付"→真值"耕赋"（现在改对 ✓），
位点 8009 处真值是"更"（更赋）。表里只留 `耕赋` 后，该处变成 `庚→耕` **错到错**。
史料侧我查了 E036 老库与 E042 新库：`耕赋` 只以"躬耕／赋诗""归耕赋"跨边界形式出现，`更赋` 也是跨边界，
两者都不能靠史料裁定，**裁定依据是真值本身**。建议：**再加一行 `更赋	geng1fu4	更付`**，两形并存。

## 五、损失 17 处改对的机制（不是删错，是结构耦合）

消失的改对：薄×3、赋×3、雨×2、史×2、魏、严、诿、鹿、会、要、辑。

V1 的替换要求 **目标词长 == ASR 错误窗长**。原表里那些"片段行"恰好等于实际窗长：

| 被删/改的行 | 实际错误窗 | 清理后 |
|---|---|---|
| `摇薄赋`（3字，咬伯父） | 3 字窗 | 改成 `轻徭薄赋`（4字）后 3 字窗匹配不上 → 薄/赋 各丢 |
| `鹿皮币`（3字，鲁皮壁） | 3 字窗 | 改成 `白鹿皮币`（4字）→ 丢 `露→鹿` 1 处改对 |
| `会要辑`（3字，慧耀及） | 3 字窗 | 删除 → 丢 会/要/辑 3 处改对 |

同一件事也带来 5 处误改消失（强→抢、之→知、事→时、解→接、时→史）与 23 处新改对
（`拔红→跋宏`×6、`担破→胆魄`、`蜻蜓→清醒` 系列等），所以总数是净赚。

**我的建议**：完整词形保留，同时在**真值证明存在的那个窗长**上保留片段行（`source` 列可标"子窗"以区分），
这不是把切分错误请回词库，而是承认"目标词长必须等于错误窗长"这一实现事实。是否这么做请园长定。

**顺带更正我自己 E042 报告里的一句话**：我写"`会要辑` 是切分片段所以不可覆盖"，从词的角度成立，
但七篇真值里那 3 个字确实就是"会要辑"，所以删它的代价是 3 处改对。已在
`build/e042_corpus/README.md` 与本记录标注。
